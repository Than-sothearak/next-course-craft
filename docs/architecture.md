# Architecture

The dashboard keeps its folder/workspace sidebar on desktop and exposes the same navigation through a Folders modal below 1024px. The modal reuses permission checks, expanded-folder state, filter-preserving links, workspace switching, and creation actions. It traps focus through the native dialog, locks background scrolling while open, returns focus on dismissal, and closes on selection or desktop resizing. Unique workspace control IDs avoid collisions between desktop/mobile navigation. Cards and loading skeletons share one/two/three/four-column breakpoints; long text and wrapping actions stay within their tracks. The shared navbar wraps action controls without clipping dropdown menus on small screens. `scripts/testing/dashboard-responsive-browser.mjs` exercises the real UI with isolated fixture data and mocked routing, without database access.

Shared text formatting includes the bundled course font families and mutually exclusive superscript/subscript marks. These controls apply to selected text, or the text object when only a caret is present. Equations use inline/block Tiptap math nodes inside existing HTML fields, preserving editable `data-latex` source rather than generated markup. Headings and other single-block title editors offer inline insertion; body text also offers display equations. Each text editor owns a portal-based native equation dialog with bounded live KaTeX validation, templates, accessible math output, one committed update, and cancellation without mutations. Main/popup editors retain their existing history and Apply/Cancel boundaries. KaTeX styles, local WOFF/WOFF2/TTF fonts, and license notices ship with the static learner and are embedded in single-file HTML. PDF handouts retain readable LaTeX source; typeset PDF equations, OCR, advanced paragraph/letter spacing, and a general symbol library remain separate work.

Presentation selection tools are shared by main slides and popup mini slides. Optional `slideGroupId`, `slideLocked`, and `slideHiddenInEditor` fields live on ordinary blocks; group IDs are local to each canvas. Shift/Ctrl/Cmd-click, a fully-contained marquee, and layer checkboxes select whole groups. Double-click or the expanded layer list enters member editing; Escape returns to the group. Bulk geometry uses rotated visual bounds, one shared bounded translation or proportional scale, and four corner handles, preserving member rotation and authored text/icon sizes. Manual resizing disables automatic text/audio frame fitting. Group creation makes members contiguous at the frontmost selected layer; group layer dragging preserves internal order. Alignment defaults to selection bounds, supports canvas targets, and distribution requires at least three units with nonnegative clear gaps.

Lock and hide controls apply to the complete group. Locked layers remain inspectable but cannot be edited through the canvas, inspector, bulk actions, or keyboard. Hidden layers are unmounted only from the editing canvas; thumbnails, learner content, progress requirements, and static exports keep them. Main-slide bulk actions commit once through the existing revision-checked draft/undo path; popup changes stay local until one Apply edit or Cancel. The version-2 clipboard carries multiple blocks while reading version-1 payloads. Paste remaps copied links and object/group IDs, preserves placement and internal stacking, and starts pasted objects visible and unlocked. Slide/course duplication keeps lock/hide flags with fresh local group IDs. Existing cover restrictions, topmost-modal routing, ownership checks, nesting limits, and 500-object/20-popup-object limits continue to apply; oversized paste is rejected atomically. `scripts/testing/slide-selection-browser.mjs` checks real mouse/touch gestures, zoom, cancellation, group editing, and popup isolation.

Coursecraft is one Next.js App Router application. Server routes and server components handle authentication, persistence, authorization, and authoring APIs. Client components provide the interactive authoring experience.

## Boundaries

Hanging Rope Cards (`hangingRopeCards`) extends the same browser-only physics system. Each card is a mass on an elastic, tension-only rope with gravity, damping, horizontal inertia and bounded pointer constraints. `lib/interactive/physics/rope.ts` reuses the shared spring integrator and frame-clock contract; the existing `PhysicsInteraction` lifecycle drives the reveal animation and awards completion only after settling. SVG strands follow the moving attachment with braided highlights, velocity-sensitive curvature and card rotation. Each card has its own glowing drop target. Releasing away from it restores the hanging position with a damped swing; releasing inside it docks the card and flips or opens its discovery. Enter/Space provides an automatic pull, Escape cancels, and reduced motion completes without continuous animation. Idle scenes and thumbnails schedule no simulation frames. Displayed SVG matrix coordinates preserve pointer accuracy at slide zoom and fullscreen sizes.

Hanging cards support one to six stable card IDs, independently editable target positions, text, optional fill colors, and one to twelve validated leaf content blocks per discovery. Peel and Rope settings share `RevealContentEditor`, native block editing and course media selection. Nested physics/popup blocks are rejected by the shared leaf schema. Duplication remaps block, card and content IDs; owner-scoped saves validate every nested asset and existing recursive export packaging remaps its references. Learners record `blockId:rope:cardId` once per successful discovery, with optional/required gating, browser and SCORM resume, review and replay. Author preview never awards progress. Standard layouts wrap cards and open a content region below; presentation cards fill their frames with an internally scrolling overlay. Exit, visibility, resize, cancellation, restart and unmount release capture and stop pending frames. `scripts/testing/hanging-rope-browser.mjs` verifies real mouse/touch interaction, scaled/fullscreen presentation, keyboard/reduced motion, compiled HTML/SCORM output and resume without Next.js APIs.

Peel to Reveal (`peelToReveal`) adds a browser-only physics interaction within the existing block and publishing boundaries. `lib/interactive/physics/engine.ts` owns the reusable spring, resistance, threshold snap, cancellation, reset and completion lifecycle; it takes a frame clock and paint callbacks and has no React, DOM, content, or server dependencies. `peel-geometry.ts` computes a clipped paper surface, pointer-dependent diagonal crease, curved reflected backside, and changing shadow. The SVG renderer and author-selected content are separate children of the shared `PeelToReveal` runtime. Animation frames update SVG geometry directly; React updates lifecycle phases only. Reduced motion uses an immediate accessible reveal. Standard cards preserve their content height during peeling and grow naturally; presentation cards fill their object and scroll content internally. Pointer coordinates use displayed bounds, including slide zoom and fullscreen transforms. Only the corner captures touch dragging; the rest of the surface retains ordinary vertical scrolling.

The versioned block validates material, solid colors, dimensions, physics presets/overrides, trigger, direction, and replay controls. Its reveal container accepts one to twelve uniquely identified ordinary text, image, gallery, video, audio, or link blocks through the existing editors and course media library. The explicit leaf schema bounds nesting to one content level and rejects recursive physics and popup blocks. Duplication remaps child IDs. Owner-scoped revision-checked saves verify nested ready assets; the existing recursive packaging remaps media and formatted HTML into static HTML/SCORM assets. Reveal content is inert and hidden from assistive technology until completion. Runtime phases expose not-started/in-progress/completed; only the settled reveal awards the stable `blockId:revealed` progress ID. Optional blocks do not gate lessons, completed reveals resume through the existing browser/SCORM adapters, and replay never deletes or duplicates recorded completion. Authoring and thumbnails never award progress. Slide exit, visibility changes, pointer cancellation and unmount release/cancel resources. The isolated `scripts/testing/peel-to-reveal-browser.mjs` exercises real pointer/touch/keyboard interaction, scaled slides, curved geometry, and compiled HTML/SCORM 1.2/2004 resume without Next.js API calls.

- `app/`: routes, layouts, and API handlers.
- `components/`: reusable authoring and learner UI.
- `app/admin/**/_components/`: admin UI colocated with the page that owns it, including dynamic user/workspace detail pages and nested settings pages. Shared navigation, loading UI, request hooks, and display helpers live in `app/admin/_components/`, alongside the `/admin` overview. Page-specific dialogs and supporting child modules live in nested `_components/` folders; reused user and workspace dialogs stay with their parent route.
- `lib/db/`: cached MongoDB connection and Mongoose model registration.
- `lib/auth/`: Auth.js configuration and server session helpers.
- `lib/schemas/`: versioned, runtime-validated content contracts shared by authoring, preview, and export.
- `lib/export/`: shared export runtime logic and learner progress interfaces.
- `lib/dashboard/`: validated folder/course operations, ownership-scoped queries, and dashboard request helpers.
- `lib/<domain>/services/`: server-side operations grouped by the dashboard, editor, and media page/API areas that use them.
- `export/`: standalone static export entry point and build configuration. It must not import Next.js server code, MongoDB, Auth.js, or private storage credentials.
- `models/`: Mongoose models; lessons and assets are independent documents rather than a giant course document.
- `tests/`: Vitest unit, component, and transactional integration tests.
- `e2e/`: Playwright tests against an isolated production build of this application.
- `scripts/testing/`: disposable replica-set lifecycle, synthetic fixtures, and production application verification; never uses the application's database configuration.

The standalone export runtime is bundled separately by Vite as a build tool inside this repository. Its build output consists only of static HTML, CSS, and JavaScript. The authenticated HTML publishing route embeds that bundle, the validated course snapshot, and owner-scoped course media in one downloadable HTML file. The SCORM 1.2 publishing route packages the same compiled export runtime with a validated snapshot, owner-scoped media, the root-level `imsmanifest.xml`, and the referenced schema files. SCORM 2004 uses the same runtime and packaged media with its own manifest and `API_1484_11` adapter. The PDF handout route validates the same course snapshot, includes owner-scoped PNG and JPEG images, and renders lesson and activity text with bundled Latin and Khmer fonts. Quiz handouts show prompts and choices without answer keys or feedback. The browser-only export saves resume and completion state through either LMS API when available; without an LMS it falls back to browser storage.

The browser-only learner view lives in `app/courses/[courseId]/preview/course-preview.tsx` and is shared by the authenticated preview route and the standalone Vite entry point. App-only navigation and publishing actions are supplied by the preview route wrapper, so the static export does not depend on Next.js APIs. The SCORM adapter lives in `export/src/scorm-runtime.ts` and depends only on browser APIs and the shared learner progress contract. Quiz best scores and passed-quiz IDs are saved with resume state; the adapter reports raw scores as attempts are graded and reports assessment success with course completion. Both outputs use `app/globals.css` for matching layout, typography, and animations.

Resume selection accepts only lesson IDs still present in the current course. A removed or stale saved slide falls back to the first available slide, preventing a presentation with navigation but no visible content after re-exporting an edited course. Valid explicit lesson requests retain priority over valid browser/LMS resume. `scripts/testing/html-export-browser.mjs` verifies the compiled runtime embedded in a single-file HTML document opened through `file://`, including fresh launch, deleted-slide recovery, valid resume, visible canvas geometry, and fully inlined fonts without network requests.

Presentation slides share `lib/editor/slide-design.ts` contracts across editor, learner preview, and static export. A lesson's optional `slideCover` selects the image cover surface; the editor inserts a separate first lesson when existing content would otherwise be hidden. Cover image and instruction audio saves verify ready ownership in the current course, and existing recursive media packaging remaps their URLs for standalone output. The Start button uses the same lesson navigation lock as ordinary slide controls. Slide objects save percentage geometry on pointer release; selecting a layer raises it only in the editor view, preserving stored position and layer order. Heading, rich-text, and statement objects reuse the existing TipTap editors directly on the canvas. The inspector's formatting toolbar targets the focused canvas editor, keeping controls outside the scaled and clipped slide. Text selection does not start object dragging; a separate move handle preserves positioning. Inline edits use the existing block HTML contracts and revision-checked autosave, so preview and static export retain their formatting.

Presentation object frames use the full slide canvas, including header and footer space. The slide master's `objectLayout: "canvas"` marker distinguishes these coordinates from earlier content-region frames. Older slides are converted to visually equivalent full-canvas positions in the editor draft and at learner/thumbnail render time; the marker is saved with normal course edits. Footer navigation stays interactive above overlapping objects, while objects can cover decorative header and footer content. Quiz slides retain their own scrollable content region.

Every selected presentation block has a move handle, eight edge/corner resize points, and a circular rotation handle, shared with popup mini slides. Pointer deltas use logical canvas pixels at any editor zoom; resizing follows the object's rotated axes and fixes the opposite edge or corner while respecting frame limits. Image/video resizing preserves proportions. Optional `slideFrame.rotation` stores validated degrees from 0 to 360; older frames remain unrotated. Shift snaps pointer rotation to 15 degrees, and the inspector offers numeric rotation. Focused handles support arrow keys, with Shift increasing movement or rotation steps. Each completed gesture commits once through normal undo/redo and revision-checked autosave; Escape, pointer cancellation and lost capture discard drafts. Text keeps inline editing, and manual resizing turns off content fitting. Manual audio height changes set `slidePlayback.fitHeight: false`; selecting an audio size preset restores automatic player fitting. Editor, thumbnails, learner preview and static HTML/SCORM use the shared frame style's individual CSS rotation, composing with entrance animations without changing saved geometry.

Presentation slide titles may be empty to leave the visible header blank. Standard lesson titles remain required by the editor snapshot schema, and blank slides use a numbered fallback in thumbnail, navigation, and accessibility labels.

Presentation object copying uses native `copy` and `paste` events for Ctrl+C/Ctrl+V and macOS Command+C/Command+V. The selected object is captured in a versioned, Zod-validated clipboard payload with its resolved frame and source course ID, using a custom MIME type plus a plain-text fallback. Pasting within the same course preserves exact coordinates, dimensions, rotation, styling, animation and media references; fresh object/nested IDs and a front layer make each copy independent. Existing target links are kept only when their target exists on the destination slide, while nested popup links are remapped. A paste is one normal undoable autosave edit and selects the new object; copying does not edit the course. Editable fields, inline text and browser text selections keep native clipboard behavior. Only the topmost editor handles clipboard events, so popup editors cannot also paste into their parent. Existing 500-object slide, 20-object popup, nesting and cover audio-instruction restrictions apply. Server ownership checks remain on the existing save path.

Presentation audio objects hide the file name by default and render the native audio bar without lesson padding. Position & size offers Small, Medium, and Large presets with 24%, 32%, and 48% canvas widths and 32, 54, and 68 pixel player heights. The validated optional `slidePlayback.audioSize` stores the chosen player density; new blocks and unconfigured players default to Small, while explicitly selected Medium/Large sizes and custom numeric widths remain available. Small also reduces title spacing, icon size and the play button when player controls are hidden. Selecting a larger preset near the right edge moves the object inside the canvas. The editor fits the object's height to its player and optional title while preserving its authored width; title wrapping and player control changes trigger another measurement in logical canvas pixels, independent of editor zoom. Audio alone allows frames down to 0.5% height so tall custom canvases retain the compact bar. Derived fitting stays with the author's edit for undo/redo. The saved frame and shared player render in mini slides, thumbnails, preview, and static exports. Authors can enable the title through Playback settings; the original file name remains the player's accessible label.

Each presentation block has an optional validated `slideBackground` with a solid hex color or a two-stop linear gradient and background opacity from 0 to 100. Blocks default to transparent in presentation layouts; their standard lesson background settings stay separate. The editor, preview, and static learner paint the fill once on the object frame, leaving nested content surfaces transparent and text/media at full opacity. The shared surface helper uses master text colors for transparent blocks and computes text contrast against the fill blended with the slide background for colored blocks.

Presentation color controls share the configured UI primitives through `ColorPicker`: 32-pixel square swatches with a 4-pixel radius, editable hex inputs, a Solid/Gradient toggle, two gradient stops, and a 0–360 degree angle. Invalid hex drafts stay local until valid and reset on blur. Color fields retain plain hex strings for solid colors and save bounded canonical two-stop `linear-gradient` strings for gradients; runtime validation rejects arbitrary CSS, URLs, and injected declarations. The shared rendering helpers paint gradient backgrounds and borders, clip gradient text, provide solid fallback colors for color-only CSS properties, and keep opacity on the fill alone. Interactive point fills, number text, radar rings, cards, dividers, process accents, lesson-map checkpoints, chart fills/strokes, and slide/header/footer colors use the same values. SVG charts and decorative backgrounds define unique gradients per instance. Inline text gradients retain their validated mark metadata through editing and reload. Preview, thumbnails, and static exports share these renderers and require no new server API.

Presentation image backgrounds, header images, and cover images support an independent optional `overlayColor` alongside their existing overlay opacity. Older slides inherit the same master/header fill or dark cover tint until an overlay color is selected. Plain image and video objects expose an optional validated `slideMediaOverlay` color and 0–100 opacity under Media source; unset overlays leave media unchanged. Shared overlay painting supports solid colors and two-stop gradients without intercepting media input or changing playback. The Course model retains master/header overlay colors, while lesson block, cover, and appearance metadata follow the existing revision-checked save path. Editor canvases, popup mini slides, thumbnails, preview, and static HTML/SCORM share the same colors; replacing media retains the overlay.

Presentation text boxes save horizontal left/center/right/justify and vertical top/middle/bottom alignment in optional `slideTextLayout` metadata. The shared text-box surface fills its object's height in both editor and learner layouts; explicit box alignment also overrides paragraph alignment inside that box. Plain image objects and videos use their intrinsic loaded dimensions, recorded as source-scoped `slideMedia` metadata. Shared sizing helpers account for the selected slide width and its object-region height (slide height minus the 108-pixel title region and configured footer height) when converting aspect ratios into percentage frames. The default object region remains 960 × 368. Dragging a resize handle or changing width, height, or scale preserves the media ratio and bounds; object-contain keeps extreme panoramic media undistorted when the minimum frame size limits its frame ratio. Replacing the source invalidates previous dimensions, and recursive asset remapping also updates the recorded source for offline exports. Other image layouts retain their authored text and card/banner behavior.

New presentation Text and Heading objects use zero block/text padding, zero corner radius, and content fitting on main slides and popup mini slides. The slide Heading insertion is a single semantic 48-pixel heading with no body paragraph; standard lesson templates retain their original layouts. Text fitting measures an unscaled clone with inherited typography in logical canvas pixels, including the editor border, so font changes and typing resize the object consistently at different zoom levels. Single-element editors and read-only previews disable TipTap's automatic trailing paragraph to keep heading-only content and its measured height intact. Explicitly authored padding, manual sizing, and existing content remain editable through the current controls.

Presentation blocks share `SlideObjectContent` in the editor, preview, and static learner. It measures natural content and scales overflowing blocks proportionally inside their saved frame, without changing authored geometry or content. Resize and mutation observers, image/media events, and font loading recompute the fit after resizing, editing, or expanding interactions. Plain images and videos retain their existing intrinsic-ratio sizing. Presentation flip cards use a shared bounded grid instead of whole-object scaling: equal cells fill the authored frame, with auto/custom columns, calculated rows, separate object/card padding, row/column gaps, corner radius, and text alignment. Spacing reduces when necessary to keep dense grids inside small objects; long face text scrolls within its cell. Optional validated `presentationLayout` settings preserve compatibility, and standard lesson cards keep their existing dimensions and breakpoints.

New main-slide and popup flip-card objects start with three independently identified cards; existing collections and standard templates retain their counts. Authors select cards and edit front/back labels and text directly on the canvas, using the object's transform handles for movement. A nearby portal toolbar offers side selection, duplication, deletion, ordering, owned-image selection, and a learner-style preview that never awards progress. Sidebar handles support pointer/touch reordering and staged keyboard pick-up/move/drop/cancel; cancelled drafts do not save. A block's shared background/text colors act as defaults, with optional per-card overrides and Use master colors. Duplicating a card or whole object assigns fresh card IDs while preserving content, images, layout and appearance. Existing card IDs remain stable during edits and ordering so per-card learner progress survives. Main-slide edits use revision-checked autosave and undo/redo; popup edits stay local until Apply. Thumbnails, preview, HTML and SCORM reuse the same browser-only grid and learner flip runtime.

The presentation editor selects slides through a responsive thumbnail panel, with Add slide at the bottom and a separate Delete slide button on every thumbnail. The panel becomes a horizontal strip on smaller screens and stays available for empty presentations. Slide thumbnail handles support pointer/touch dragging and Space/Enter plus arrow-key reordering in both layouts, using the existing drag-and-drop primitives. A drop updates the lesson order in one undoable, autosaved change and keeps the selected slide open. Crossing a section boundary moves the slide into the destination section and normalizes section-local orders, preserving slide IDs, blocks, cover settings, and quiz answers. Preview and standalone export use the resulting lesson order; cancelling a drag leaves content unchanged. The shared footer also exposes Previous, Restart, and Next in the editor on cover, content, and quiz slides. Editor navigation changes the selected slide without recording learner progress; Restart replays canvas media without changing authored content. Deletion uses the existing draft history and revision-checked save, renumbers the remaining lessons in that section, and selects a neighboring slide when deleting the active slide. Deleting another slide preserves the current selection. An empty presentation retains Add slide. Thumbnails render scaled, inert copies at the selected slide dimensions of the shared slide and cover surfaces, actual block previews, quiz questions, master backgrounds, and footer branding. They update from the current draft and preserve object geometry and layer order. Native media never autoplays in thumbnails, and their decorative surfaces use separate DOM markers so they do not participate in canvas editing or learner playback/progress. Thumbnail selection and deletion use sibling buttons around the inert preview to avoid nested interactive controls. Learner presentation navigation stays in the shared preview/export shell.

The presentation inspector uses 380 pixels on desktop and 420 pixels on wider screens, stacking below the canvas on smaller screens. Master slide, Object block, and Cover page tabs separate global design, selected-object controls, and cover content on content, cover, and quiz slides. Tabs support arrow/Home/End keyboard navigation and retain their mounted panel state. Each tab starts with all settings sections expanded and has Show all and Hide all actions plus individual section toggles with labeled 14–15 pixel icons. Collapse state belongs to each tab, keeps editors mounted, and never changes saved course data. Position/size, appearance, alignment, media, playback, and content controls use compact grids, 12-pixel control text, and consistent section spacing. Selecting or adding an object opens Object block settings; cover slides open Cover page settings. The cover panel opens an existing cover or creates one without replacing existing content or quiz questions. Content, cover, and quiz slides share editor canvas zoom controls with Fit and 25–200% presets plus zoom steps. The editor canvas workspace uses a light-gray surround with a white toolbar; both the workspace and canvas have square corners. Manual zoom scrolls inside the canvas viewport; Fit responds to available space and resets scrolling. Zoom stays in editor view state across slide selection, leaving saved block geometry and exported slide dimensions unchanged. Pointer movement continues to use the displayed object's bounds when converting screen movement to slide coordinates.

Presentation numeric settings share the `components/ui/number-input` control built from the configured Input and Button primitives. Authors can clear fields and finish partial, negative, or decimal entries without intermediate clamping. Valid numbers update the draft; blur or Enter bounds completed numbers, empty entries restore the saved value, and Escape cancels the edit. Visible increase/decrease buttons and Up/Down keys change values by exactly 1, preserving supported decimal precision. Buttons respect field limits and disabled/read-only state. Geometry, media scale, crop pixels, typography, animation, guides, charts, map checkpoints, navigation, footer spacing, and gradient angles use the same behavior on main slides and popup mini slides. Opacity sliders retain a companion typed percentage field. Custom canvas dimensions stay local until Apply.

Content and quiz slide headers are directly editable plain lesson titles with a 160-character limit. Pointer or keyboard focus selects the header and opens its text settings in the inspector, independently of block selection. Optional per-lesson `slideHeaderStyle` stores font family, size (12 to 72 pixels), weight, italic, underline, alignment, and color. Slides without an override inherit master header typography; Use master header text style removes the override. Formatting changes follow normal undo/redo, revision-checked owner-scoped saves, lesson/course duplication, thumbnails, preview, and standalone exports. Shared title fitting keeps long learner titles visible; alignment and font changes use the same typography as the editor. Cover hero typography retains its existing cover settings.

Presentation gallery image groups fill their authored object width and height using bounded grid rows and columns. Each image fills its cell with proportional cover cropping, instead of a fixed 4:3 tile or lesson-width padding. Resizing the object reflows the grid directly, without changing image sources or adding media aspect-ratio constraints to the group. Editor, thumbnails, learner preview, popup mini slides, and standalone exports share this gallery renderer, including stagger animation and original-image fullscreen viewing. Standard lesson galleries retain their existing proportions.

Objects & layers lists every slide object from front to back, using later object order to break equal layer values consistently with rendering. Dedicated handles support pointer/touch dragging and Space/Enter plus arrow-key reordering, with Escape to cancel. A drop changes only the existing objects' layer values in one undoable, autosaved lesson update; content order and object geometry stay fixed. Front and Back use the same ordering. Thumbnails, preview, and static exports retain the saved layers. All selected-object controls, including text formatting, belong to one settings card with Duplicate and Delete actions in its header.

Object settings start with Content & interaction (Text content for text blocks), followed by Media source when available and Position & size. Navigation & progress is last. Selecting one editable media object exposes Replace media on the canvas in main slides and popup mini slides. The shared native dialog fits the visible canvas at the current zoom and scroll position, with an internally scrolling course media library and gallery image selector. It reuses existing uploads, file validation, ownership checks, and replacement behavior; image/video replacement clears source-specific crops. Main-slide changes use normal undo/redo and autosave; popup replacements stay local until Apply and are discarded by Cancel. Locked, hidden, and multiple selections have no quick replacement action.

Presentation image and uploaded-video objects support a source-scoped, validated crop rectangle. The Crop inspector opens a shared dialog with drag/keyboard movement, corner resizing, aspect presets, pixel fields, Apply, Cancel, and Reset. Draft selections stay local until Apply, which saves the crop, original dimensions, and fitted object proportions in one undoable change. Cropping preserves the source file and media ownership rules; replacing media clears the crop, and source mismatches are ignored. Proportional resizing uses the cropped dimensions. Editor, thumbnails, preview, image fullscreen views, and static HTML/SCORM output share crop geometry. Cropped videos keep playback, seeking, mute, captions, completion, and Restart controls within their visible viewport; thumbnail videos remain inert and never autoplay. Recursive media packaging remaps crop source references together with the original media URL.

Presentation labeled graphics keep a viewport at the authored object's full size. Optional `data.objectFit` selects fill, contain, cover, none, or scale-down, defaulting to fill. A shared source rectangle maps hotspot display, popup placement, and dragging to the same fitted image geometry for images, built-in maps, and illustrated scenes. Opening a hotspot preserves that image size; its explanation scrolls inside a bounded popup beside the point. Popup placement uses unscaled image coordinates, so slide zoom, fullscreen, and content fitting keep it anchored correctly. The image clips overflow without becoming a scroll container, preventing focus on edge points from shifting the image or popup. Each point's optional color overrides the shared default, while an optional shared radar color remains independent. Authors can drag points directly on the slide and edit their title, explanation, and color in the point's popup. A drag remains local until pointer release, creating one undo step and one draft change; cancellation discards it. The inspector also provides individual color controls and a reset to the default. Interactive image settings offer image selection from the media library or an image URL, without a free map picker. New interactive images start with an image placeholder. Existing saved `mapTemplate` backgrounds remain readable for compatibility; choosing an image clears that legacy selection and retains normal asset ownership checks. Editor canvases, thumbnails, learner preview, and static exports share the image and point rendering.

Each labeled-graphic point also supports optional `radarEnabled` metadata. Existing points retain their animated radar; authors can disable it independently in the canvas popup or inspector. A disabled radar removes the pulse while preserving the point, popup, dragging, and learner progress. Preview and static exports honor the same setting, including mini-game points.

Every presentation block supports optional `slideBorderRadius` metadata from 0 to 100 canvas pixels, defaulting to 0. Optional `slideBorder` stores a width from 0 to 24 pixels (default 0), solid hex color, solid/dashed/dotted/double style, and opacity from 0 to 100. Optional `slideShadow` selects None, Small, Medium, or Large. Shared frame painting applies borders, corners and shadows in the editor, thumbnails, preview and static learner; selection uses a separate outline. Border opacity affects the stroke alone. Explicit saved radii remain editable. Interactive point buttons retain their own shape. The inspector can apply the selected radius across the presentation in one undoable edit, or reset the selected object's border, corners and shadow together while preserving its fill and content.

Main slides and popup mini slides share logical-canvas alignment and snap helpers. During movement, an eight-screen-pixel tolerance snaps the object to canvas left/right/top/bottom, horizontal/vertical center, the visible header's lower edge, or the footer's upper edge. The closest reachable target on each axis wins; rotated visual bounds are used within the saved frame's canvas constraints. Editor-only guides label active targets and clear on release, Escape or pointer cancellation. A view-state Snap to guides toggle persists across slide switches, and Alt bypasses snapping during a drag. The inspector provides explicit edge, center, header and footer alignment buttons through the same normal undo/autosave path. Hidden headers supply no header target, and hidden footers align with the canvas bottom. Audio's compact frame schema permits its top position up to 99.5% when its height allows, so it can reach the bottom without being enlarged. These changes preserve the single App Router application and browser-only static learner boundary.

The object inspector displays Left, Top, Width, and Height in unscaled canvas pixels with up to two decimal places. Horizontal values use the selected slide width and vertical values use its object-region height (960 × 368 by default). Edits convert back to the existing percentage frames through the shared bounds and media-proportion helpers, so changing zoom or opening older snapshots preserves their layout.

Snap to guides sits in the canvas top bar beside zoom controls; popup mini slides group it in their own canvas top bar. Its compact label retains the Alt-drag hint as a tooltip. The course editor navbar shows one accessible save-status icon in both active lessons and presentation settings, replacing the overview's floating save badge. Invalid titles, failed saves and revision conflicts show an alert icon with explanatory text and tooltips; existing retry/reload actions remain in the error banner. Presentation master settings include an optional validated `header` with transparent, color, or image backgrounds, a separate title color, image crop position, and overlay opacity. ## Verification and performance

`npm run check` runs zero-warning lint, generates route types before strict TypeScript checking, and runs all Vitest tests with a disposable transactional MongoDB. A missing database prerequisite fails the full check instead of silently skipping integration coverage. `npm run test:unit` is the explicit database-free subset. Browser tests and the HTTP author workload seed synthetic users and sessions into randomly named databases, start this application's production build on loopback, and remove their databases afterward. Provider credentials are disabled for those journeys.

The CI workflow runs full checks, the static learner build, and production browser tests on Linux, plus unit/type checks on Windows. The 100-author performance job is an optional manual CI run; its reports record workload, environment, percentiles, failures, and persisted saves. See [the verification baseline](verification-baseline.md) for prerequisites, commands, results, and measurement limits.

## Media Storage settings

The requested Phase 15 storage extension uses the existing `PlatformSettings` singleton (`_id: platform`). `mediaStorageProvider` defaults to S3, and `mediaStorageRevision` detects conflicting administration saves; `mediaLocalDirectory` holds the selected local directory for new files. Settings and connection-test endpoints under `/api/admin/settings/media-storage` explicitly require a fresh active Super Admin role. Saves test the provider before a security transaction rechecks authorization, serializes changes, updates the singleton, and creates an audit event. AI settings remain independent.

Lessons include a file attachment block. Its uploads use the existing private asset lifecycle with an opaque MIME type and a bounded 250 MB size; the learner preview renders a download link using the original filename. HTML embeds attachment bytes, SCORM packages them as media assets, and PDF handouts list their names without embedding the files.

`lib/media/providers/types.ts` defines upload, read, delete and metadata operations. The S3 adapter reuses the existing AWS client, private bucket, presigned uploads and reads. The local adapter writes bounded streams to exclusive temporary files, syncs them, and atomically links the final server-generated key without overwriting existing data. The authenticated local PUT route bypasses Proxy body buffering and independently verifies origin, account, course edit access and the pending asset's metadata. Completion checks sizes, S3 metadata and a bounded file signature before setting ready status. Failed validation removes the stored object before its pending record; failed cleanup preserves that record.

The Super Admin storage settings also report filesystem free space for the currently selected local folder. The authenticated settings API validates a requested folder before measuring it; inaccessible capacity is returned as unavailable without blocking provider management. S3 has no fixed bucket capacity to report.

New assets retain `storageProvider`, `storageKey`, and the existing `objectKey`. New local assets also retain an immutable absolute `storageDirectory`; local assets predating folder selection fall back to the original `MEDIA_LOCAL_DIRECTORY`. Missing provider always means historical S3; missing storage key falls back to `objectKey`. Reads, deletes and offline exports resolve each asset independently of the current singleton. Switching does not migrate media. The Super Admin folder chooser is bounded by `MEDIA_LOCAL_ROOT` (defaulting to the parent of the environment upload directory), lists visible directories only, and rejects files, traversal outside the root, and symlinks. Folder selection is tested before the audited settings update. Reads, deletes, pending upload completion, copies and exports resolve each saved local directory independently of later settings changes. Existing media directories and the legacy environment fallback must remain mounted while files exist. S3 bucket/region remain deployment configuration. The UI never receives cloud credentials. Private serving checks current course access on every request, supports byte ranges for both providers, streams the response, and forces documents to download with nosniff. HTML remains the existing self-contained single file with embedded bytes; both SCORM formats package bytes with relative media paths and preserve their shared LMS adapter. The standalone learner has no provider or database imports. See `docs/media-storage.md` for deployment and backup requirements.

Lesson audio blocks appear under Multimedia and use the existing private audio upload lifecycle (MP3, M4A, OGG, WAV, and WebM, up to 100 MB). Editor saves require ready audio assets owned by the current course. A shared native audio player renders in authoring, learner preview, and static exports; HTML embeds the bytes and SCORM packages relative media files. PDF handouts list the audio filename. Audio blocks are added manually and excluded from AI generation. Uploaded audio records completion when playback ends, matching video: restricted navigation and required Continue gates wait for it. Free and sequential reading completion stay unchanged. Completion persists through the shared learner progress adapter in preview and static exports; empty audio placeholders do not block progress.

## Slide interactive presentation template

Course creation accepts `courseLayout: "standard" | "slides"`, validated with Zod and stored on the existing Course document. A slide course starts with one content lesson; each ordered lesson is one slide and retains the existing block schema, revision-checked save path, permissions, media ownership checks, and export behavior. The editor opens the first slide in a dedicated workspace with a responsive thumbnail panel, per-slide deletion, an Add slide action, and a canvas fitted to available space, defaulting to 960 × 540 (16:9). Slide blocks carry bounded positions, sizes, and layer order; new slide object templates add compact versions of existing text, media, and interactive blocks. The course-level master slide stores optional validated pixel dimensions, a theme preset, colors, background design or image, footer, and slide-number option. Master slide settings offer Widescreen (16:9), Standard (4:3), Square (1:1), landscape/portrait orientation, and custom integer dimensions from 480 to 3840 pixels per side. Size changes apply to every content, cover, and quiz slide through the existing undo/redo and autosave path; older courses retain 960 × 540. Editor zoom, thumbnails, preview, and static exports share the selected dimensions while object frames remain percentages and media preserves its source aspect ratio. Selected slide media objects expose a direct course media-library chooser in the slide inspector for images, video, audio, galleries, labeled graphics, and attachments; it reuses owner-scoped upload validation and asset URLs. Older slide blocks without positions receive a deterministic grid arrangement. The learner preview and standalone exports use a dedicated presentation shell with full-screen and keyboard navigation. Full-screen presentation hides the preview toolbar and scales the entire canvas at its authored aspect ratio to fit the viewport, using white letterboxing when the screen ratio differs. Each slide can independently show or hide its Previous/Next/Restart navigation buttons; when enabled without a footer, they float over the slide. Small menu and fullscreen buttons are absolute overlays just inside the canvas's top-left and top-right corners. They scale with the slide and take no space in its content layout. The buttons check shared progression locks; the menu opens the existing learner outline over the slide, with course and section progress, search, and locked slide states. The surrounding presentation view is white. The stage, objects, master surface, and presentation controls live in route `_components` folders. Both runtimes share the existing ordered lessons, block interactions, completion tracking, and navigation locks. Course duplication preserves the layout. Older courses default to standard. This requested slice of Phase 10 does not add other course templates.


Audio instruction is a separate optional content block on presentation covers and content slides, with a course-owned audio file, autoplay on slide entry, editable text, independent Show icon/Show text toggles, and solid/gradient colors. Cover settings now contain only the welcome notice, alongside the existing cover appearance and layout controls. Cover object geometry uses the canvas height above its footer; ordinary slides retain their header and footer object region. Only audio instruction objects are permitted on covers, keeping other lesson content visible on content slides. Both object regions share editing, layers, moving/resizing, deletion, undo, saving, thumbnails, preview and static HTML/SCORM rendering. Instruction audio never autoplays in authoring or thumbnails, pauses when leaving the slide or removing/replacing the object, and supports footer Restart. Existing cover instruction files are converted to optional instruction blocks on load, preserving the file, notice and automatic/manual preference; legacy cover/Start triggers map to autoplay on entry. The old cover audio source is cleared in the returned draft to prevent duplicate playback and is persisted through the normal save path. Raw legacy learner data remains backward compatible. Instruction assets use the existing ownership-scoped audio validation and recursive export packaging.
