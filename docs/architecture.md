# Architecture

Coursecraft is one Next.js App Router application. Server routes and server components handle authentication, persistence, authorization, and authoring APIs. Client components provide the interactive authoring experience.

## Boundaries

- `app/`: routes, layouts, and API handlers.
- `components/`: reusable authoring and learner UI.
- `app/admin/**/_components/`: admin UI colocated with the page that owns it, including dynamic user/workspace detail pages and nested settings pages. Shared navigation, loading UI, request hooks, and display helpers live in `app/admin/_components/`, alongside the `/admin` overview. Page-specific dialogs and supporting child modules live in nested `_components/` folders; reused user and workspace dialogs stay with their parent route.
- `lib/db/`: cached MongoDB connection and Mongoose model registration.
- `lib/auth/`: Auth.js configuration and server session helpers.
- `lib/schemas/`: versioned, runtime-validated content contracts shared by authoring, preview, and export.
- `lib/export/`: shared export runtime logic and learner progress interfaces.
- `lib/dashboard/`: validated folder/course operations, ownership-scoped queries, and dashboard request helpers.
- `lib/<domain>/services/`: server-side operations grouped by the dashboard, editor, and media page/API areas that use them.
- `export/`: standalone static export entry point and build configuration. It must not import Next.js server code, MongoDB, Auth.js, or private storage credentials.
- `models/`: Mongoose models; lessons and assets are independent documents rather than a giant course document.
- `tests/`: Vitest unit, component, and transactional integration tests.
- `e2e/`: Playwright tests against an isolated production build of this application.
- `scripts/testing/`: disposable replica-set lifecycle, synthetic fixtures, and production application verification; never uses the application's database configuration.

The standalone export runtime is bundled separately by Vite as a build tool inside this repository. Its build output consists only of static HTML, CSS, and JavaScript. The authenticated HTML publishing route embeds that bundle, the validated course snapshot, and owner-scoped course media in one downloadable HTML file. The SCORM 1.2 publishing route packages the same compiled export runtime with a validated snapshot, owner-scoped media, the root-level `imsmanifest.xml`, and the referenced schema files. SCORM 2004 uses the same runtime and packaged media with its own manifest and `API_1484_11` adapter. The PDF handout route validates the same course snapshot, includes owner-scoped PNG and JPEG images, and renders lesson and activity text with bundled Latin and Khmer fonts. Quiz handouts show prompts and choices without answer keys or feedback. The browser-only export saves resume and completion state through either LMS API when available; without an LMS it falls back to browser storage.

The browser-only learner view lives in `app/courses/[courseId]/preview/course-preview.tsx` and is shared by the authenticated preview route and the standalone Vite entry point. App-only navigation and publishing actions are supplied by the preview route wrapper, so the static export does not depend on Next.js APIs. The SCORM adapter lives in `export/src/scorm-runtime.ts` and depends only on browser APIs and the shared learner progress contract. Quiz best scores and passed-quiz IDs are saved with resume state; the adapter reports raw scores as attempts are graded and reports assessment success with course completion. Both outputs use `app/globals.css` for matching layout, typography, and animations.

Presentation slides share `lib/editor/slide-design.ts` contracts across editor, learner preview, and static export. A lesson's optional `slideCover` selects the image cover surface; the editor inserts a separate first lesson when existing content would otherwise be hidden. Cover image and instruction audio saves verify ready ownership in the current course, and existing recursive media packaging remaps their URLs for standalone output. The Start button uses the same lesson navigation lock as ordinary slide controls. Slide objects save percentage geometry on pointer release; selecting a layer raises it only in the editor view, preserving stored position and layer order. Heading, rich-text, and statement objects reuse the existing TipTap editors directly on the canvas. The inspector's formatting toolbar targets the focused canvas editor, keeping controls outside the scaled and clipped slide. Text selection does not start object dragging; a separate move handle preserves positioning. Inline edits use the existing block HTML contracts and revision-checked autosave, so preview and static export retain their formatting.

Presentation object frames use the full slide canvas, including header and footer space. The slide master's `objectLayout: "canvas"` marker distinguishes these coordinates from earlier content-region frames. Older slides are converted to visually equivalent full-canvas positions in the editor draft and at learner/thumbnail render time; the marker is saved with normal course edits. Footer navigation stays interactive above overlapping objects, while objects can cover decorative header and footer content. Quiz slides retain their own scrollable content region.

Presentation slide titles may be empty to leave the visible header blank. Standard lesson titles remain required by the editor snapshot schema, and blank slides use a numbered fallback in thumbnail, navigation, and accessibility labels.

Each presentation block has an optional validated `slideBackground` with a solid hex color or a two-stop linear gradient and background opacity from 0 to 100. Blocks default to transparent in presentation layouts; their standard lesson background settings stay separate. The editor, preview, and static learner paint the fill once on the object frame, leaving nested content surfaces transparent and text/media at full opacity. The shared surface helper uses master text colors for transparent blocks and computes text contrast against the fill blended with the slide background for colored blocks.

Presentation color controls share the configured UI primitives through `ColorPicker`: 32-pixel square swatches with a 4-pixel radius, editable hex inputs, a Solid/Gradient toggle, two gradient stops, and a 0–360 degree angle. Invalid hex drafts stay local until valid and reset on blur. Color fields retain plain hex strings for solid colors and save bounded canonical two-stop `linear-gradient` strings for gradients; runtime validation rejects arbitrary CSS, URLs, and injected declarations. The shared rendering helpers paint gradient backgrounds and borders, clip gradient text, provide solid fallback colors for color-only CSS properties, and keep opacity on the fill alone. Interactive point fills, number text, radar rings, cards, dividers, process accents, lesson-map checkpoints, chart fills/strokes, and slide/header/footer colors use the same values. SVG charts and decorative backgrounds define unique gradients per instance. Inline text gradients retain their validated mark metadata through editing and reload. Preview, thumbnails, and static exports share these renderers and require no new server API.

Presentation text boxes save horizontal left/center/right/justify and vertical top/middle/bottom alignment in optional `slideTextLayout` metadata. The shared text-box surface fills its object's height in both editor and learner layouts; explicit box alignment also overrides paragraph alignment inside that box. Plain image objects and videos use their intrinsic loaded dimensions, recorded as source-scoped `slideMedia` metadata. Shared sizing helpers account for the selected slide width and its object-region height (slide height minus the 108-pixel title region and configured footer height) when converting aspect ratios into percentage frames. The default object region remains 960 × 368. Dragging a resize handle or changing width, height, or scale preserves the media ratio and bounds; object-contain keeps extreme panoramic media undistorted when the minimum frame size limits its frame ratio. Replacing the source invalidates previous dimensions, and recursive asset remapping also updates the recorded source for offline exports. Other image layouts retain their authored text and card/banner behavior.

Presentation blocks share `SlideObjectContent` in the editor, preview, and static learner. It measures natural content and scales overflowing blocks proportionally inside their saved frame, without changing authored geometry or content. Resize and mutation observers, image/media events, and font loading recompute the fit after resizing, editing, or expanding interactions. Plain images and videos retain their existing intrinsic-ratio sizing. Presentation flip cards use compact card surfaces and narrower container breakpoints, keeping ordinary grids at full size and dense grids fully visible. Standard lesson flip cards keep their existing dimensions and breakpoints.

The presentation editor selects slides through a responsive thumbnail panel, with Add slide at the bottom and a separate Delete slide button on every thumbnail. The panel becomes a horizontal strip on smaller screens and stays available for empty presentations. Slide thumbnail handles support pointer/touch dragging and Space/Enter plus arrow-key reordering in both layouts, using the existing drag-and-drop primitives. A drop updates the lesson order in one undoable, autosaved change and keeps the selected slide open. Crossing a section boundary moves the slide into the destination section and normalizes section-local orders, preserving slide IDs, blocks, cover settings, and quiz answers. Preview and standalone export use the resulting lesson order; cancelling a drag leaves content unchanged. The shared footer also exposes Previous, Restart, and Next in the editor on cover, content, and quiz slides. Editor navigation changes the selected slide without recording learner progress; Restart replays canvas media without changing authored content. Deletion uses the existing draft history and revision-checked save, renumbers the remaining lessons in that section, and selects a neighboring slide when deleting the active slide. Deleting another slide preserves the current selection. An empty presentation retains Add slide. Thumbnails render scaled, inert copies at the selected slide dimensions of the shared slide and cover surfaces, actual block previews, quiz questions, master backgrounds, and footer branding. They update from the current draft and preserve object geometry and layer order. Native media never autoplays in thumbnails, and their decorative surfaces use separate DOM markers so they do not participate in canvas editing or learner playback/progress. Thumbnail selection and deletion use sibling buttons around the inert preview to avoid nested interactive controls. Learner presentation navigation stays in the shared preview/export shell.

The presentation inspector uses 380 pixels on desktop and 420 pixels on wider screens, stacking below the canvas on smaller screens. Master slide, Object block, and Cover page tabs separate global design, selected-object controls, and cover content on content, cover, and quiz slides. Tabs support arrow/Home/End keyboard navigation and retain their mounted panel state. Each tab starts with all settings sections collapsed and has Show all and Hide all actions plus individual section toggles with labeled 14–15 pixel icons. Collapse state belongs to each tab, keeps editors mounted, and never changes saved course data. Position/size, appearance, alignment, media, playback, and content controls use compact grids, 12-pixel control text, and consistent section spacing. Selecting or adding an object opens Object block settings; cover slides open Cover page settings. The cover panel opens an existing cover or creates one without replacing existing content or quiz questions. Content, cover, and quiz slides share editor canvas zoom controls with Fit and 25–200% presets plus zoom steps. The editor canvas workspace uses a light-gray surround with a white toolbar; both the workspace and canvas have square corners. Manual zoom scrolls inside the canvas viewport; Fit responds to available space and resets scrolling. Zoom stays in editor view state across slide selection, leaving saved block geometry and exported slide dimensions unchanged. Pointer movement continues to use the displayed object's bounds when converting screen movement to slide coordinates.

Presentation image and uploaded-video objects support a source-scoped, validated crop rectangle. The Crop inspector opens a shared dialog with drag/keyboard movement, corner resizing, aspect presets, pixel fields, Apply, Cancel, and Reset. Draft selections stay local until Apply, which saves the crop, original dimensions, and fitted object proportions in one undoable change. Cropping preserves the source file and media ownership rules; replacing media clears the crop, and source mismatches are ignored. Proportional resizing uses the cropped dimensions. Editor, thumbnails, preview, image fullscreen views, and static HTML/SCORM output share crop geometry. Cropped videos keep playback, seeking, mute, captions, completion, and Restart controls within their visible viewport; thumbnail videos remain inert and never autoplay. Recursive media packaging remaps crop source references together with the original media URL.

Presentation labeled graphics keep a viewport at the authored object's full size. Optional `data.objectFit` selects fill, contain, cover, none, or scale-down, defaulting to fill. A shared source rectangle maps hotspot display, popup placement, and dragging to the same fitted image geometry for images, built-in maps, and illustrated scenes. Opening a hotspot preserves that image size; its explanation scrolls inside a bounded popup beside the point. Popup placement uses unscaled image coordinates, so slide zoom, fullscreen, and content fitting keep it anchored correctly. The image clips overflow without becoming a scroll container, preventing focus on edge points from shifting the image or popup. Each point's optional color overrides the shared default, while an optional shared radar color remains independent. Authors can drag points directly on the slide and edit their title, explanation, and color in the point's popup. A drag remains local until pointer release, creating one undo step and one draft change; cancellation discards it. The inspector also provides individual color controls and a reset to the default. Interactive image settings offer image selection from the media library or an image URL, without a free map picker. New interactive images start with an image placeholder. Existing saved `mapTemplate` backgrounds remain readable for compatibility; choosing an image clears that legacy selection and retains normal asset ownership checks. Editor canvases, thumbnails, learner preview, and static exports share the image and point rendering.

Each labeled-graphic point also supports optional `radarEnabled` metadata. Existing points retain their animated radar; authors can disable it independently in the canvas popup or inspector. A disabled radar removes the pulse while preserving the point, popup, dragging, and learner progress. Preview and static exports honor the same setting, including mini-game points.

Every presentation block supports optional `slideBorderRadius` metadata from 0 to 100 canvas pixels, defaulting to 12. The shared frame and content surfaces honor the value in the editor, thumbnails, preview, and static learner. Setting 0 produces square corners while interactive point buttons retain their circular shape. The inspector can apply the selected radius to all blocks across the presentation through one undoable draft change.

The object inspector displays Left, Top, Width, and Height in unscaled canvas pixels with up to two decimal places. Horizontal values use the selected slide width and vertical values use its object-region height (960 × 368 by default). Edits convert back to the existing percentage frames through the shared bounds and media-proportion helpers, so changing zoom or opening older snapshots preserves their layout.

Presentation master settings include an optional validated `header` with transparent, color, or image backgrounds, a separate title color, image crop position, and overlay opacity. The shared header background fills the 108-pixel title area on content and quiz slides in the editor, thumbnails, preview, and static exports; image covers retain their own hero design. Older presentations inherit the master background and title color. Header images use the existing course image library, ready owner/course asset checks, revision-checked autosave, undo/redo, and recursive offline asset packaging.

Every presentation object exposes a Required for progress switch under Object block → Navigation & progress. The optional validated `requiredForProgress` boolean defaults to the previous required behavior when absent. Restricted navigation and its activity percentage count only required objects, while optional interactions still record their normal completion IDs for resume and learner feedback. Static objects add no separate activity task. Optional Continue blocks do not hide following content, hold reading progress, or gate navigation; required Continue blocks still wait for required activities above them. Free and sequential navigation retain their existing rules, and quiz passing remains controlled by the quiz. The metadata follows the existing undo/redo, autosave, and snapshot/HTML/SCORM export paths.

Every slide block can align its bottom edge directly with the footer. Dragging within eight displayed pixels of that edge snaps the block and shows a guide, with a matching Align to footer inspector action. The object region extends to the configured footer; saved image/video dimensions refit the media frame to the current region while retaining its natural proportions. Snapping preserves block width, height, and layer and uses the same percentage frame in preview/export.

Video and audio blocks have optional `slidePlayback` settings for autoplay and player controls. Older blocks keep manual playback and enabled controls. Audio objects also support optional showFileName metadata under Object block → Playback. The Show file name switch defaults to visible for existing audio. Turning it off removes the visible title row in the editor canvas, thumbnails, preview, and static exports while retaining the stored filename, accessible player label, playback controls, and completion tracking. The flag uses the existing undo, save, and snapshot paths. The presentation runtime activates only the visible slide's media and pauses media when leaving it; authoring does not autoplay. A minimal Play/Pause button remains when timelines are hidden, including a Play fallback if browser policy blocks autoplay. Presentation video controls have transparent backgrounds and appear on pointer hover, keyboard focus, or a touch tap; leaving with the mouse hides them without interrupting playback. Enabled audio controls stay visible. The first ended event records the existing watched/listened progress; completion remains available across revisits and resume. Turning player controls off keeps native and cropped-video timelines hidden after completion, restricted-navigation unlocking, replay, and restored progress. Completion never overrides the author's control setting. Restart slide in the footer synchronously restarts only the active slide's native video/audio without clearing progress or other interactions. Standard course media keeps its existing players. The metadata and shared playback components also run in static exports without server APIs.

The optional master `background` selects a solid color, one of six built-in abstract SVG designs, or a course media-library image with crop position and color-overlay opacity. Designs use the master background/accent palette and require no external assets. The shared background surface renders in the editor, preview, and static learner; image covers retain their separate image settings. Saves verify that master images are ready, owned by the author, and belong to the course. The Course subdocument retains these settings, and recursive media packaging remaps master image URLs for offline HTML/SCORM use. Older masters without `background` retain their theme appearance.

Presentation slides share a full-width footer, defaulting to 64 pixels high, at the bottom of the fixed canvas, including image covers and quizzes. Learner Previous/Next controls sit inside this footer alongside the optional slide number and branding. The optional master `footer` stores text/logos/both mode, up to twelve ordered image logos with descriptions, footer padding, background/text colors, and top-border visibility, color, and width. Footer padding applies to the entire container around text, logos, slide numbers, and navigation in every content mode. Horizontal padding ranges from 0 to 64 canvas pixels and vertical padding from 0 to 32. Effective vertical padding preserves a 24-pixel content area in compact footers. Defaults of 20 horizontal and 8 vertical pixels preserve existing footers. The shared logo layout fits up to six images per row within the available space across editor, preview, and static exports. Master settings store horizontal logo gaps from 0 to 32 canvas pixels (default 8), vertical row gaps from 0 to 12 (default 4), left/center/right/space-between justification (default center), and top/middle/bottom alignment (default middle). Each row packs the actual image widths with the selected gap and alignment; proportional width limits keep all images and gaps inside the footer. Each logo uses its intrinsic dimensions and aspect ratio, scaling down proportionally only when its available cell is smaller. The grid uses the full padded footer height without fixed logo width or height caps, preserving wide, tall, square, and small artwork without stretching or cropping. Footer text uses its content width and wraps within two lines. With logos present, its width is capped at half of the branding area so long labels leave room for the logos. Existing `footerText` and slide-number settings remain compatible; masters without custom footer settings inherit their master colors. The inspector reuses the course media library to add or replace logos and supports reordering/removal. Saves verify all stored logos are ready images owned within the current course, deduplicating repeated asset checks. Course persistence and recursive media packaging retain and remap the footer settings and assets for offline HTML/SCORM. The object region ends at the top of the footer.

Phase 11 learner navigation adds search across lesson and quiz titles, collapsible section groups, per-section completion summaries, and a saved course-level progression mode. Authors can allow free navigation, require completion of each lesson in sequence, or require completion of activities and Continue gates before unlocking the next lesson. These rules run in the shared learner view, so the authenticated preview and standalone export use the same locks and resume state.

Free and sequential navigation mark content lessons complete after the learner reads all revealed sections to the end; interactions do not block completion unless a Continue button requires completion above. Those Continue gates require both reading and the interactions above in every navigation mode. Restricted navigation also requires all lesson activities before marking a lesson complete and unlocking the next one. Its lesson progress ring combines reading progress and completed activities, and reaches 100% only when both are complete. Next section stays hidden while any Continue gate remains unrevealed or incomplete, including gates with completion set to None. Completion does not fabricate interaction records. Graded quiz lessons still require a passing attempt in every mode. The same completion snapshot drives preview checkmarks, saved resume state, and SCORM completion reporting.

Course themes are validated in `lib/editor/theme.ts`, persisted in the course document, and included in the revision-checked editor snapshot. The course editor exposes palette presets, custom brand and accent colors, and local system font choices. The shared learner view maps these values to CSS custom properties, so the authenticated preview, HTML package, and both SCORM formats render the same branding without loading external fonts or assets.

Theme settings also configure the course introduction cover: Gradient, Solid color, Image, Waves, Geometric, or Editorial. A shared cover surface renders template thumbnails, the live settings preview, and the learner overview with container-based typography. Authors can set cover/text colors and alignment; image covers use the existing course media library, with image descriptions, cropping position, and overlay opacity. The optional `theme.cover` subdocument preserves older themes without a migration. Saves verify ready image ownership within the current course. Existing recursive HTML/SCORM media packaging includes cover assets and rewrites their URLs for offline use; the shared cover schema accepts those rewritten image sources while the save service requires an owned media-library URL.

Code examples use the existing richText block with escaped source inside pre/code elements. Seven presets combine six themes with optional titles and explanation paragraphs above or below the code. The shared TipTap code extension preserves theme/language attributes and applies syntax colors as view decorations, keeping stored source text intact. Lesson rich text and learner previews accept multiple document elements so titles, paragraphs, and code survive editing and export; title and statement editors retain their single-element behavior. AI code seeds can include nullable codeExample metadata that selects the same presets and supplies the explanation; old seeds without it remain supported.


Presentation interaction buttons support a course-owned image or 24 preset icons, a fixed pixel button size (80px by default), nine alignments inside the object box, independent solid/gradient colors, a radar toggle, and an action that opens either a selected block from the same lesson or an editable popup mini slide. Popup slides reuse validated text/image/video/audio objects, inline text editing, pixel geometry controls, canvas dragging/resizing, media selection and playback settings. Authors configure popup dimensions, colors and fade/zoom/slide animation; reduced-motion preferences disable animation. Native modal popups render outside the scaled slide while retaining the course theme and fullscreen container, fit narrow viewports, and pause/unmount their media on close or slide change. Opening a configured button records its required activity; optional or unavailable buttons do not block navigation. Duplicating lessons/sections remaps linked block IDs, and deleting a target clears its links. Save validation checks every trigger and nested media asset for ready ownership in the current course; existing recursive HTML/SCORM packaging includes and remaps those assets. Audio instruction blocks expose autoplay on slide entry and optional icon/text controls for manual playback when a browser blocks automatic sound.

## Persistence and security

Process-step blocks support Classic cards, Numbered, Timeline, Spotlight, and Minimal layouts, with optional accent colors and numbered badges. Existing blocks keep the Classic layout. Content settings and prebuilt template changes preserve authored step IDs and instructions; editing or adding steps retains the selected presentation settings. The shared process renderer and its navigation/card components are used by the editor, preview, and static HTML/SCORM learner export, with the same interaction tracking in every layout.

Process-step layouts use their container width for timeline columns, card padding, progress, and navigation controls. Narrow previews stack timeline navigation above the card and allow the step list to scroll horizontally. Previous/Next controls stack below 320px; long instructions wrap within the card. Navigation labels display two lines while the accessible button name and active card retain the complete title.

The author preview navbar Edit action routes to the active lesson and, when applicable, its visible content block using the lesson editor's `blockId` query parameter. The lesson route accepts a block target only when it belongs to the loaded owner-scoped lesson; the editor scrolls to that block and focuses its inline text or opens its content settings. Standalone learner exports omit author controls.

The shared preview measures the space below its toolbar and fits mobile/tablet frames to both available dimensions. The actual screen width controls the compact lesson menu. Only the selected lesson participates in layout; inactive lessons stay mounted to preserve interactions and reading positions. Each lesson has one bounded vertical scroller, and progress is recalculated when its height changes.

Next/Previous section buttons use a short directional slide within the bounded lesson reader. The outgoing lesson briefly becomes an inert absolute overlay, so navigation never adds stacked lesson heights or scrolls an outer container. The transition cancels on another navigation, reader resize, device/orientation change, or leaving Learn mode; completion restores the inactive lesson's hidden state. Reduced-motion preferences and browsers without the animation API use an immediate switch.

Flip-card grids, typography, and padding respond to their own container width, including simulated mobile frames inside a desktop browser. Narrow blocks stack cards in one column; larger blocks allow two columns, or three for a three-card set when space permits. Both faces size to their content, wrap long labels, and constrain images without changing flip interactions or completion tracking.

MongoDB is accessed only from server-side code. Every data access path must scope reads and writes to the authenticated owner or workspace. Zod validates untrusted input before persistence. Mongoose schemas add database-level validation, indexes, and timestamps. Secrets stay in server environment variables.

The Phase 2 dashboard uses `/api/folders`, `/api/courses`, and `/api/dashboard`. Folder deletion is blocked while it contains courses or subfolders. Course deletion requires an exact title confirmation and marks the document as recently deleted, preserving its content references. The dashboard filters deleted documents from normal listings.

The dashboard supports Cache Components and Partial Prefetching with a static navbar and matching skeletons for the account menu, folder sidebar, folder cards, and course cards. URL parameters resolve behind Suspense; the authenticated profile, folder navigation, and workspace listing stream through separate boundaries. Navigation and listing queries run concurrently with request-scoped session deduplication. Shared client state connects sidebar actions to workspace dialogs and refreshes folder counts after mutations. Initial server data is reused without an immediate duplicate API request; filter changes show the same card skeletons and cancel superseded requests.

Course duplication copies validated sections and lessons, the ready media library, and referenced source media into independent private objects in the active storage provider and destination-scoped asset records. Authors can copy a personal course into a shared workspace or copy between workspaces; copies into a different workspace start at the root. It remaps nested media URLs, rich text, quiz images, dashboard covers, and theme covers. Course-local content identifiers and quiz answer relationships remain intact; database IDs and asset URLs are new. The new course is created only after its media and lessons are ready. Source revision checks reject inconsistent reads, and failure cleanup removes only the attempted copy's records and files, with best-effort logging if cleanup itself fails.

Phase 13 collaboration uses shared workspaces that own their courses, folders, and media. The workspace owner retains content ownership; memberships grant owner/admin/editor/viewer access, and every dashboard, editor, media, generation, and publishing operation checks the member's role before using that owner scope. Personal data remains in the personal scope. Courses record their creating account separately from the workspace owner so the author byline remains correct for teammates; older courses fall back to their owner. Invitation tokens are random, stored only as SHA-256 hashes, expire after seven days, and can only be accepted by a signed-in account whose email matches the invitation. Workspace folder uniqueness is scoped by owner, workspace, parent, and normalized name. Run `MONGODB_URI=... npm run migrate:workspace-folder-index` once against an existing database before deploying workspace folders; the migration creates the new unique index and removes the two previous folder uniqueness indexes.

The Phase 3 course page is served at `/courses/[courseId]/edit`, with lessons edited individually at `/courses/[courseId]/edit/lessons/[lessonId]`. Adding a lesson uses `/api/courses/[courseId]/lessons`; editor saves persist through `/api/courses/[courseId]/editor`. It stores ordered section metadata on the course and stores lessons as separate documents with stable editor IDs. Autosaves validate the complete snapshot and check the course revision. Replica sets use a MongoDB transaction; standalone MongoDB uses an atomic course revision lock and restores the prior course and lesson snapshot if a write fails. A stale revision returns a conflict so the editor can preserve the author's local changes and ask them to reload.

Duplicating content keeps the current editor route and saves the new lesson in its source section. Copies receive independent block/question/choice data and IDs, with quiz answer keys mapped to the copied choices. The content actions menu can move a lesson or quiz to another section of the same course, appending it there and normalizing source/destination ordering. Both actions use the editor's existing history and revision-checked save path.

Phase 4 media uploads use short-lived S3 presigned POST policies. The application stores the private object key and ownership metadata in `Asset`, and lesson blocks reference an authenticated `/api/assets/[assetId]/file` route rather than a bucket URL. Configure S3 bucket CORS to allow `POST`, `GET`, and `HEAD` from the development and production app origins; keep S3 Block Public Access enabled. The application IAM identity needs `s3:PutObject`, `s3:GetObject`, and `s3:DeleteObject` on the configured bucket prefix.

AI course generation is an authenticated, app-only Node.js route. Prompt-only input produces a structured draft that is validated against generation constraints and the shared block schema before it reaches the editor. PDF/PPTX source generation runs as an owner-scoped, resumable MongoDB job: the server indexes the document, extracts bounded page batches, plans lesson ranges, generates Pre/Learn/Post stages independently, validates source coverage, and checkpoints each completed unit. Uploaded source bytes are held temporarily in the job document while bounded extraction is running, then cleared when the inventory is complete. Job and checkpoint records expire after 24 hours. Authors review the generated outline and apply it through the existing revision-checked editor save path. Generated illustrations are stored as owner-scoped private assets in the active storage provider and inserted through their authenticated asset routes; they are supplemental and do not count as preserved original visuals.

Each structured generation stage shares a two-request allowance and one deadline across transport retries, JSON repairs, and application-validation corrections. Temporary rate limits, selected server errors, and temporary connection failures may retry after a short jittered delay, honoring Retry-After; delays above 30 seconds or beyond the stage deadline stop instead of retrying early. Billing, authentication, request-configuration, output-limit, and timeout failures do not automatically resubmit generation. Provider schemas enforce quiz option bounds, exact activity counts, and text limits before application validation. Prompt-only drafts also repair incorrect lesson counts or missing template activities within the same allowance; source stages retain their existing checkpoints for manual resume.

Learn and prompt-only generation use a compact response schema with only the fields relevant to each block type. The server restores neutral unused settings and validates the same editor seeds; existing checkpoints remain readable. All structured text stages, including source inventory and planning, share a ten-minute deadline across their requests. Learn writing uses low reasoning effort with the selected model. A dedicated Node HTTPS transport lets that deadline cover response headers and the complete body without Node fetch's shorter header timeout. The generation route allows sixteen minutes for text plus queued image storage and cleanup; course and source-job leases last seventeen minutes so another request cannot start while this work is still active. Reverse proxies and hosting limits must allow the full route duration. Image requests retain their separate 75-second timeout. If a source group times out or reaches its output limit, the job checkpoints smaller parts for subsequent requests, splitting between complete pages or source elements without cutting code listings. Completed parts are saved independently and merged in source order into the originally planned lesson; page grouping, titles, and source references remain intact. The progress response reports saved parts while retaining the two parent steps. Older timed-out jobs prepare smaller parts when resumed, using their saved source inventory and plan. A coverage-repair timeout retains an earlier validated draft with an explicit coverage warning rather than discarding it.

Lesson depth profiles request developed explanations, worked examples, common mistakes, guided application, and a recap. Detailed lessons target 10–14 teaching blocks; application checks require at least eight distinct teaching blocks and 2,800 characters of explanatory content, excluding headings, controls, questions, surveys, and raw code. Concise and very detailed settings scale these requirements, while source lessons and recovery parts scale to the supplied material without inventing content. Insufficient drafts use the existing correction allowance. The entire course allows at most two inline knowledge checks and one survey, with no repeated prompts; dedicated Pre/Post quizzes retain their configured counts. Source stages share the remaining activity budget across lessons and saved parts. Final assembly also constrains historical checkpoints and removes trailing Continue controls. Paragraphs remain separate in rich text, and short source lessons are no longer padded with placeholder blocks.

The generation dialog always shows two parent steps while generating. Prompt-only requests show Prepare prompt as complete and Generate course as active with indeterminate progress until the single request finishes. File requests show initial source steps immediately, then use the job's reported progress. Each run clears stale progress, and the loading panel can scroll on short screens without clipping the steps. Displaying progress does not send extra generation requests.

Block-selection guidance maps supplied numeric comparisons and trends to native charts independently of the generated-image setting, procedures to process steps, and qualitative details or recall to suitable interactive formats. Source planning retains visual kinds and visible labels so it can recommend charts for actual source data. Each source lesson and resumed part receives bounded format counts and recent activity formats from completed content to reduce repeated sequences while preserving author preferences and suitable explanations. Variety is guidance rather than a block quota. Source coverage includes chart values/descriptions and labeled-graphic markers; chart units may be stored in the mapped chart's title, description, or field labels without duplicating the values in prose.

The prompt field starts with editable instructions to follow the selected structure and settings. Optional instruction buttons append source-preservation, code-explanation, guided-practice, summary/next-lesson, or Continue-button guidance without replacing authored text or submitting a request. The controls prevent duplicate additions and respect the existing 5,000-character limit; prompts do not hardcode a language or grouping mode.

Authors can cancel an active generation or a saved source job from the dialog. Cancellation aborts browser requests, stops subsequent source stages, and clears the matching saved reference; a provider request already sent may still finish. Late responses cannot replace a newer run. Source cancellation is owner/course scoped, preserves an already completed draft, and removes checkpoints even when an in-flight stage writes after cancellation. Missing or expired saved jobs clear with a retry message and retain the prompt/settings; starting fresh requires an explicit Generate draft action.

## Authentication

Auth.js v5 uses the existing MongoDB adapter with a validated profile wrapper that creates server-generated user IDs and explicitly persists `viewer`/`pending` for new registrations. Native OAuth writes bypass Mongoose defaults, so authorization fields are protected in the wrapper. Sign-in records last-login time and a credential-free audit event. Reauthentication never resets approval or permissions. Google requires a verified email; linking a new Google identity to an Admin/Super Admin additionally requires an already authenticated session for the same active account. Active users can explicitly connect providers from `/account-status`.

Platform authorization lives in `lib/auth/policy.ts` and `lib/auth/authorization.ts`. Current MongoDB account status and role policies authorize each privileged request; OAuth session/JWT claims only identify the actor. Missing/invalid authorization data fails closed. Statuses are pending, active, rejected and suspended; platform roles are Super Admin, Admin, Editor and Viewer. Mutable role policies and optional per-user allowlists can only narrow immutable role ceilings. Approval is independent of authentication. Pending/rejected/suspended users retain their account-status and sign-out paths.

Existing owner/workspace checks in `lib/workspaces/access.ts` now intersect platform permissions with ownership, workspace membership, and explicit `CourseAssignment` roles. Administrators need `courses.manage_all` plus the requested operation; author roles never grant access to another private course by themselves. Media, editor, generation, publishing and exports share these checks. Publishing requires both publish and export permissions. Media files stream through the authenticated route instead of exposing reusable private download URLs; static learner exports stay independent of authentication APIs.

`lib/admin/` provides scoped queries and transactional mutations for `/admin` and its APIs. A singleton security control serializes mutations and bootstrap so simultaneous changes cannot remove the last active Super Admin. Sensitive changes and their safe audit metadata commit together. Ownership transfer updates course/asset/job scopes, preserves creator/content IDs, moves the course into the target's personal root, and rejects active saves, generation leases/jobs or upload policies. Maintenance scripts explicitly migrate legacy accounts to pending when status is absent and bootstrap one existing account by protected ID and operator confirmation. Administration requires authenticated transactional MongoDB; see `docs/admin-operations.md` for rollout, migration, bootstrap and test instructions.

Admin server sections and navigation use `'use cache: private'`, `cacheLife({ stale: 300 })`, and `admin`/section-specific tags. The client router can reuse their personalized output for five minutes. Initial authorized reads travel with the server payload through `AdminResourceProvider`, avoiding a second API request on entry. Admin navigation, shortcuts, and detail links use `AdminPrefetchLink`: prefetching is disabled until hover, keyboard focus, or touch enables per-link prefetching for that destination. This also defers personalized app-shell reads until intent. These private scopes opt into a cookie-based session gate because `connection()` is prohibited inside private caches. Current database permissions still protect data reads and every API operation. Filters and refreshes use the existing uncached APIs; successful mutations and explicit refreshes call an authenticated Server Action to invalidate the `admin` tag and `/admin` layout, including cached lists and navigation permissions.

Admin navigation browser tests use Next.js's `@next/playwright` `instant()` helper. The isolated e2e runner enables `EXPOSE_TESTING_API=1` for its dedicated production build; ordinary builds leave the testing API disabled. URL parameters resolve under Suspense before their primitive values enter the private cache scopes.

Workspace administration at `/admin/workspaces` and `/api/admin/workspaces` requires a current active Super Admin, independently of workspace membership and the ordinary `workspaces.manage` permission. It provides paginated name/owner search, owner and content counts, bounded member/invitation/course details, and workspace name updates. Updates and deletions check the workspace's `updatedAt` value to reject stale requests. Deletion requires the exact workspace name and rejects any workspace with courses (including recently deleted courses) or folders. An empty workspace, its memberships and its invitations are removed in the same transaction as the audit event. Course administration accepts a workspace filter for navigation from workspace details.

## Verification and performance

## Media Storage settings

The requested Phase 15 storage extension uses the existing `PlatformSettings` singleton (`_id: platform`). `mediaStorageProvider` defaults to S3, and `mediaStorageRevision` detects conflicting administration saves; `mediaLocalDirectory` holds the selected local directory for new files. Settings and connection-test endpoints under `/api/admin/settings/media-storage` explicitly require a fresh active Super Admin role. Saves test the provider before a security transaction rechecks authorization, serializes changes, updates the singleton, and creates an audit event. AI settings remain independent.

Lessons include a file attachment block. Its uploads use the existing private asset lifecycle with an opaque MIME type and a bounded 250 MB size; the learner preview renders a download link using the original filename. HTML embeds attachment bytes, SCORM packages them as media assets, and PDF handouts list their names without embedding the files.

`lib/media/providers/types.ts` defines upload, read, delete and metadata operations. The S3 adapter reuses the existing AWS client, private bucket, presigned uploads and reads. The local adapter writes bounded streams to exclusive temporary files, syncs them, and atomically links the final server-generated key without overwriting existing data. The authenticated local PUT route bypasses Proxy body buffering and independently verifies origin, account, course edit access and the pending asset's metadata. Completion checks sizes, S3 metadata and a bounded file signature before setting ready status. Failed validation removes the stored object before its pending record; failed cleanup preserves that record.

The Super Admin storage settings also report filesystem free space for the currently selected local folder. The authenticated settings API validates a requested folder before measuring it; inaccessible capacity is returned as unavailable without blocking provider management. S3 has no fixed bucket capacity to report.

New assets retain `storageProvider`, `storageKey`, and the existing `objectKey`. New local assets also retain an immutable absolute `storageDirectory`; local assets predating folder selection fall back to the original `MEDIA_LOCAL_DIRECTORY`. Missing provider always means historical S3; missing storage key falls back to `objectKey`. Reads, deletes and offline exports resolve each asset independently of the current singleton. Switching does not migrate media. The Super Admin folder chooser is bounded by `MEDIA_LOCAL_ROOT` (defaulting to the parent of the environment upload directory), lists visible directories only, and rejects files, traversal outside the root, and symlinks. Folder selection is tested before the audited settings update. Reads, deletes, pending upload completion, copies and exports resolve each saved local directory independently of later settings changes. Existing media directories and the legacy environment fallback must remain mounted while files exist. S3 bucket/region remain deployment configuration. The UI never receives cloud credentials. Private serving checks current course access on every request, supports byte ranges for both providers, streams the response, and forces documents to download with nosniff. HTML remains the existing self-contained single file with embedded bytes; both SCORM formats package bytes with relative media paths and preserve their shared LMS adapter. The standalone learner has no provider or database imports. See `docs/media-storage.md` for deployment and backup requirements.

Lesson audio blocks appear under Multimedia and use the existing private audio upload lifecycle (MP3, M4A, OGG, WAV, and WebM, up to 100 MB). Editor saves require ready audio assets owned by the current course. A shared native audio player renders in authoring, learner preview, and static exports; HTML embeds the bytes and SCORM packages relative media files. PDF handouts list the audio filename. Audio blocks are added manually and excluded from AI generation. Uploaded audio records completion when playback ends, matching video: restricted navigation and required Continue gates wait for it. Free and sequential reading completion stay unchanged. Completion persists through the shared learner progress adapter in preview and static exports; empty audio placeholders do not block progress.
