# Architecture

At phone widths up to 640px, scrolling interactive blocks cap rendered titles at 18px and body text at 14px, preserving smaller text and restoring authored sizes on desktop. Lesson wrappers identify interactive content for the shared responsive typography runtime; semantic headings, activity legends and flip-card front text receive the title cap. Ordinary lesson text retains its 22px/16px limits, quiz assessments retain their own 16px/12px styling, and presentation canvases keep geometric scaling. The rules apply to nested/revealed content and static learners without changing saved font formatting.

Timeline is a version-1 informational block with one to twenty uniquely identified entries, bounded editable labels/titles/body text and optional formatted HTML. Three presets share one browser-only renderer: a centered alternating vertical line (single-sided on narrow containers), a horizontally scrolling line, and stacked cards with a centered connecting line. Line/marker colors inherit the live course primary color unless an explicit solid/gradient accent is saved. Default titles are 20px and body text 16px. Authors format labels, titles and paragraphs directly through the existing selection toolbar, and use shared settings to change layout, add, reorder or remove entries without losing content.

The picker exposes all three Timeline templates; slide/popup insertion, layers, native scrolling inside object bounds, undo/save, snapshots, clipboard and duplication use the existing block paths. Duplication remaps entry IDs. Layout template replacement preserves authored entries and color overrides. Owner-scoped saves check course-asset references in formatted timeline content, including nested popups, and generic recursive packaging remaps links for static HTML/SCORM. PDF handouts retain labels and readable formatted text. AI generation may select Timeline for source-supported historical events, milestones, or phases, with bounded event counts and generated IDs; it does not invent dates or add completion IDs. `scripts/testing/timeline-browser.mjs` verifies layouts, text formatting, ordering, live theme colors, mobile overflow, scaled slides, popup toolbar isolation and six compiled offline learners without application/network requests.

Step slider defaults to L (920px) content width in shared authoring and learner layout, including new templates and generated blocks. Explicit custom widths remain authoritative, and the slider has no smaller internal width cap.

Step slider exposes a visible theme-colored progress bar below its step badge using the shared `Progress` primitive. Its position follows the current step, reaches 100% on the final card and updates when navigating backward, with accessible step-count text and reduced-motion-aware width transitions. The template preview shows the same bar.

The shared AI draft converter explicitly assigns `style: "slider"` to newly generated process-step blocks in direct and staged course generation. Existing saved blocks and manual template selections keep their styles; legacy steps without a style still resolve to Classic cards.

Step slider (`processSteps.data.style: "slider"`) is a process-step preset with a simple image-first card, a theme-colored step badge with its original 12px label above, and 44px Previous/Next arrows vertically centered in side columns above 640px and centered below the card on narrower containers. Next and Previous animate the new card from opposite sides over 280ms; reduced-motion preferences disable the transition. The shared card retains optional media/files, formatted titles/instructions, course theme inheritance and 20px/16px default typography. Previous is hidden on the first step and Next on the final step, with both hidden for a single step; their layout columns remain reserved to keep the card stable. Arrow-key navigation preserves bounded selection; editable text keeps caret keys. Standard authoring, main/popup slides, thumbnails and offline learners reuse the existing step schema, media ownership, undo/save, playback cleanup and completion paths. Templates and style settings expose the new preset without rewriting existing blocks. The process-step browser check also verifies desktop arrow centering, mobile controls below the card, themed badges, directional/reduced-motion transitions, touch targets and narrow layouts and compiled Standard/Presentation exports.

Accordion/tab items and all process-step styles default to 20px titles and 16px explanations in shared authoring and learner components. Existing inline font overrides remain authored; accordion titles carry the title role so mobile interactive sizing applies the 18px title cap and 14px body cap. Navigation labels and step-number decorations keep their independent sizing. Preview and standalone exports reuse the same rendering.

Standard quiz sections use a named inline-size container so phone previews and actual mobile screens share compact styling at widths up to 640px: 16px questions, 12px answers/supporting copy, 8px outer padding, 12px card padding and 8px choice padding. Action buttons wrap while retaining their touch heights. Desktop typography and presentation canvas sizing retain existing behavior. The same shared components/CSS ship in static learner exports; `scripts/testing/mobile-quiz-browser.mjs` verifies computed fonts/padding, grading, desktop restoration and framed preview sizing.

Course generation keeps a topic title and its paragraphs/bullets together in one editable rich-text block, using the existing title-and-paragraph structure. Shared generation instructions prefer combined title/body seeds. Assembly converts heading seeds that contain explanations to rich text and folds adjacent standalone headings into untitled or matching-title text/code seeds, preserving source-ID unions, source order, exact code and existing native-size chunking. Distinct topic headings and interaction formats remain independent. This applies to new drafts through direct and staged generation; saved courses are not rewritten.

Scrolling learner blocks share `ResponsiveBlockText`: screens up to 640px cap headings and explicit title fields at 22px, and paragraphs/list text at 16px, including large authored inline sizes such as 72px list text; smaller text retains its original size. Formatted title fields carry a runtime text-role marker so paragraph markup inside a title receives the title cap. It measures fonts before applying runtime-only CSS variables, so nested inline formatting scales once and newly revealed content follows the same rule. Resize and content observers restore desktop sizes and use the actual framed preview screen width. Editable regions and presentation canvases retain their own sizing; slides already scale geometrically. The shared learner imports this browser-only component in preview and static HTML/SCORM without changing saved content. `scripts/testing/mobile-block-text-browser.mjs` checks real computed sizes, inheritance, revealed content, framed previews and desktop restoration.

List items support a title followed by supporting paragraphs under the same marker. The shared rich-text toolbar's Text below list title action and Shift+Enter split a paragraph inside the current item and clear inherited inline marks; Enter retains normal next-item behavior. Ordinary list HTML preserves this structure through template changes, saving and static learner rendering without new schema fields or server dependencies.

Step images reuse the image block's `PreviewImage` fullscreen viewer, retaining the shared media frame, fit and focal point. Click or keyboard activation opens the original image in authoring, learner preview and standalone HTML/SCORM; thumbnails stay noninteractive. The shared viewer isolates cancel/close events so dismissing an enlarged image inside a popup leaves its parent open. The process-step browser check covers scaled/fullscreen slides, nested popups, mobile sizing, keyboard/Escape, focus restoration and offline image sources.

Process steps support optional titles (empty titles stay hidden for learners), direct title/instruction editing through the shared selected-text formatting toolbar, safe links, editable Previous/Next labels, and independent course-owned `media` and `attachment` slots per step. Media selection filters images, video, or audio by the selected type; files of any type can be offered separately for download. Legacy downloads in the media slot remain visible and move to the attachment slot when media is added. Optional block-level `mediaLayout` gives every step image/video the same bounded pixel width/height, Cover/Contain/Fill fit, and focal point; the default frame is 640×360 with Contain, and it scales proportionally on narrow screens. Presentation step blocks with media scroll within their object bounds rather than changing scale with each step's text or attachments. Bounded optional `titleHtml`, `bodyHtml`, `previousLabel` and `nextLabel` fields preserve legacy plain-text blocks and pass through existing draft, undo, snapshot and recursive static packaging paths. Plain settings edits clear corresponding markup. Standard blocks, main slides and popup mini slides share the editor; learner preview and standalone HTML/SCORM share rendering. Media pauses on step/slide exit and cleanup, and thumbnails stay inactive. Owner-scoped saves verify both slots, including nested steps. Every new process style inherits the live course primary color and derived tint unless an explicit accent is saved; authors can restore inheritance. PDF handouts extract formatted text and list both filenames. `scripts/testing/process-steps-browser.mjs` verifies real editing, formatting/links, independent media/files, consistent image/video frames, live theme changes, scaled/modal/mobile layouts, and compiled Standard/Presentation exports without application API requests.

Selected-text formatting keeps its initial viewport position while authors change text settings, including reflow from font sizes, headings and lists. A new text selection or viewport resize can reposition it. Color and link editors use separate owned popovers beside the toolbar, preserving the selection and keeping the toolbar open when a child panel is dismissed. Both panels stay inside the active native dialog or fullscreen container and fit narrow viewports. Link entry retains the shared URL validation and Apply/Cancel/Remove behavior.

Gallery blocks retain their existing grid layout unless authors select the scrolling carousel template or layout. Optional validated `layout` and `imageFit` settings, plus per-image `fit` overrides, stay on the ordinary gallery data. The shared browser-only carousel uses native horizontal scrolling and center snapping, Previous/Next buttons, image-click navigation, arrow/Home/End keys, responsive alignment and reduced-motion support. It fills slide frames and popup canvases, keeps thumbnails inactive, and preserves settings through media replacement, save/undo, clipboard, duplication and existing recursive asset packaging. Standard, Presentation and standalone HTML/SCORM use the same component without server APIs.

Chart blocks use the live course primary color when `data.color` is absent. Optional validated field colors override the chart color independently, including solid or gradient fills and matching donut/stacked legends. Existing explicit chart colors remain intact; authors can restore theme/chart inheritance from the shared settings. Columns reserve headroom above the highest bar so value labels stay separated. The shared chart renderer and snapshot fields serve authoring, preview, and static HTML/SCORM exports.

Accordion and tab blocks share animated panels with a 240 ms expand/collapse or fade/slide transition, immediate inactive/inert closing content, and reduced-motion support. Existing entrance staggering and section progress IDs stay independent of panel motion. Authors edit titles and multiline explanations directly inside Standard blocks, presentation canvases and popup mini slides through a formatting popup that appears when title or explanation text is selected. The shared toolbar is placed near the selection outside clipped/scaled canvases, inside the active native dialog or fullscreen container. A caret alone shows no popup; clearing the selection, clicking outside or pressing Escape dismisses it while formatting controls retain the selected range. Editable titles sit outside section/tab buttons so selecting or typing text cannot toggle a section. Bounded optional `titleHtml`/`bodyHtml` retain formatting alongside legacy plain `title`/`body`, including save, undo/redo, reload, preview and static HTML/SCORM. Plain settings edits clear the corresponding saved markup, and PDF handouts extract readable text from formatted fields.

Every image block layout supports optional validated `imageFit` (Cover, Contain, or Fill), `imagePosition` (center, top, bottom, left, or right), and `imageAspectRatio` (layout default, 4:3, 16:9, 1:1, or 3:4). Caption images retain Contain and natural sizing by default; banners, split layouts, cards, overlays, and covers retain their previous Cover and frame sizing. Explicit ratios override cover height; saved legacy `coverPosition` remains the cover focal-point fallback. Plain slide images share these controls, fitting a selected ratio inside the object's existing bounds; cropped images fit the crop rather than the original source. The shared layout and media renderer apply settings in authoring, thumbnails, learner preview, and static HTML/SCORM without changing fullscreen image viewing. Settings follow normal save, undo, duplication, and asset packaging paths. Covers retain independent height, overlay darkness, editable title, and supporting copy.

Video/audio blocks expose an Allow skipping switch in Standard content settings and Presentation playback settings. The optional validated block field `allowSkipping` resolves to true when absent, including existing courses. Turning it off blocks forward seeking beyond continuous played coverage until playback finishes; rewinding and completed review remain available. This setting is independent of Required for progress: optional media can still restrict seeking without gating course completion. When skipping is allowed, reaching playback end records the existing completion ID without requiring continuous coverage. Both settings retain normal save, undo/redo, duplication and static HTML/SCORM serialization. The original players remain in use with no added lock notes, badges or custom controls.

The dashboard keeps its folder/workspace sidebar on desktop and exposes the same navigation through a Folders modal below 1024px. The modal reuses permission checks, expanded-folder state, filter-preserving links, workspace switching, and creation actions. It traps focus through the native dialog, locks background scrolling while open, returns focus on dismissal, and closes on selection or desktop resizing. Unique workspace control IDs avoid collisions between desktop/mobile navigation. Cards and loading skeletons share one/two/three/four-column breakpoints; long text and wrapping actions stay within their tracks. The shared navbar wraps action controls without clipping dropdown menus on small screens. `scripts/testing/dashboard-responsive-browser.mjs` exercises the real UI with isolated fixture data and mocked routing, without database access.

Shared text formatting includes the bundled course font families and mutually exclusive superscript/subscript marks. These controls apply to selected text, or the text object when only a caret is present. Equations use inline/block Tiptap math nodes inside existing HTML fields, preserving editable `data-latex` source rather than generated markup. Headings and other single-block title editors offer inline insertion; body text also offers display equations. Each text editor owns a portal-based native equation dialog with bounded live KaTeX validation, templates, accessible math output, one committed update, and cancellation without mutations. Main/popup editors retain their existing history and Apply/Cancel boundaries. KaTeX styles, local WOFF/WOFF2/TTF fonts, and license notices ship with the static learner and are embedded in single-file HTML. PDF handouts retain readable LaTeX source; typeset PDF equations, OCR, advanced paragraph/letter spacing, and a general symbol library remain separate work.

Presentation selection tools are shared by main slides and popup mini slides. Optional `slideGroupId`, `slideLocked`, and `slideHiddenInEditor` fields live on ordinary blocks; group IDs are local to each canvas. Shift/Ctrl/Cmd-click, a fully-contained marquee, and layer checkboxes select whole groups. Double-click or the expanded layer list enters member editing; Escape returns to the group. Bulk geometry uses rotated visual bounds, one shared bounded translation or proportional scale, and four corner handles, preserving member rotation and authored text/icon sizes. Manual resizing disables automatic text/audio frame fitting. Group creation makes members contiguous at the frontmost selected layer; group layer dragging preserves internal order. Alignment defaults to selection bounds, supports canvas targets, and distribution requires at least three units with nonnegative clear gaps.

Lock and hide controls apply to the complete group. Locked layers remain inspectable but cannot be edited through the canvas, inspector, bulk actions, or keyboard. Hidden layers are unmounted only from the editing canvas; thumbnails, learner content, progress requirements, and static exports keep them. Main-slide bulk actions commit once through the existing revision-checked draft/undo path; popup changes stay local until one Apply edit or Cancel. The version-2 clipboard carries multiple blocks while reading version-1 payloads. Paste remaps copied links and object/group IDs, preserves placement and internal stacking, and starts pasted objects visible and unlocked. Slide/course duplication keeps lock/hide flags with fresh local group IDs. Existing cover restrictions, topmost-modal routing, ownership checks, nesting limits, and 500-object/20-popup-object limits continue to apply; oversized paste is rejected atomically. `scripts/testing/slide-selection-browser.mjs` checks real mouse/touch gestures, zoom, cancellation, group editing, and popup isolation.

Coursecraft is one Next.js App Router application. Server routes and server components handle authentication, persistence, authorization, and authoring APIs. Client components provide the interactive authoring experience.

## Boundaries

Hanging Rope Cards (`hangingRopeCards`) extends the same browser-only physics system. Each card is a mass on an elastic, tension-only rope with gravity, damping, horizontal inertia and bounded pointer constraints. `lib/interactive/physics/rope.ts` reuses the shared spring integrator and frame-clock contract; the existing `PhysicsInteraction` lifecycle drives the reveal animation and awards completion only after settling. SVG strands follow the moving attachment with braided highlights, velocity-sensitive curvature and card rotation. Each card has its own glowing drop target. Releasing away from it restores the hanging position with a damped swing; releasing inside it docks the card and flips or opens its discovery. Enter/Space provides an automatic pull, Escape cancels, and reduced motion completes without continuous animation. Idle scenes and thumbnails schedule no simulation frames. Displayed SVG matrix coordinates preserve pointer accuracy at slide zoom and fullscreen sizes.

Hanging cards support one to six stable card IDs, independently editable target positions, text, optional fill colors, and one to twelve validated leaf content blocks per discovery. Peel and Rope settings share `RevealContentEditor`, native block editing and course media selection. Nested physics/popup blocks are rejected by the shared leaf schema. Duplication remaps block, card and content IDs; owner-scoped saves validate every nested asset and existing recursive export packaging remaps its references. Learners record `blockId:rope:cardId` once per successful discovery, with optional/required gating, browser and SCORM resume, review and replay. Author preview never awards progress. Standard layouts wrap cards and open a content region below; presentation cards fill their frames with an internally scrolling overlay. Exit, visibility, resize, cancellation, restart and unmount release capture and stop pending frames. `scripts/testing/hanging-rope-browser.mjs` verifies real mouse/touch interaction, scaled/fullscreen presentation, keyboard/reduced motion, compiled HTML/SCORM output and resume without Next.js APIs.

Peel to Reveal (`peelToReveal`) adds a browser-only physics interaction within the existing block and publishing boundaries. `lib/interactive/physics/engine.ts` owns the reusable spring, resistance, threshold snap, cancellation, reset and completion lifecycle; it takes a frame clock and paint callbacks and has no React, DOM, content, or server dependencies. `peel-geometry.ts` computes a clipped paper surface, pointer-dependent diagonal crease, curved reflected backside, and changing shadow. The SVG renderer and author-selected content are separate children of the shared `PeelToReveal` runtime. Animation frames update SVG geometry directly; React updates lifecycle phases only. Reduced motion uses an immediate accessible reveal. Standard cards preserve their content height during peeling and grow naturally; presentation cards fill their object and scroll content internally. Pointer coordinates use displayed bounds, including slide zoom and fullscreen transforms. Only the corner captures touch dragging; the rest of the surface retains ordinary vertical scrolling.

The versioned block validates material, solid colors, dimensions, physics presets/overrides, trigger, direction, and replay controls. Its reveal container accepts one to twelve uniquely identified ordinary text, image, gallery, video, audio, or link blocks through the existing editors and course media library. The explicit leaf schema bounds nesting to one content level and rejects recursive physics and popup blocks. Duplication remaps child IDs. Owner-scoped revision-checked saves verify nested ready assets; the existing recursive packaging remaps media and formatted HTML into static HTML/SCORM assets. Reveal content is inert and hidden from assistive technology until completion. Runtime phases expose not-started/in-progress/completed; only the settled reveal awards the stable `blockId:revealed` progress ID. Optional blocks do not gate lessons, completed reveals resume through the existing browser/SCORM adapters, and replay never deletes or duplicates recorded completion. Authoring and thumbnails never award progress. Slide exit, visibility changes, pointer cancellation and unmount release/cancel resources. The isolated `scripts/testing/peel-to-reveal-browser.mjs` exercises real pointer/touch/keyboard interaction, scaled slides, curved geometry, and compiled HTML/SCORM 1.2/2004 resume without Next.js API calls.

- `app/`: routes, layouts, and API handlers.
- `components/`: reusable authoring and learner UI.
- `app/admin/**/_components/`: admin UI colocated with the page that owns it, including dynamic user/workspace detail pages and nested settings pages. Shared navigation, loading UI, request hooks, and display helpers live in `app/admin/_components/`, alongside the `/admin` overview. Page-specific dialogs and supporting child modules live in nested `_components/` folders; reused user and workspace dialogs stay with their parent route.
- `lib/db/`: cached MongoDB connection and Mongoose model registration.
- `lib/auth/`: Auth.js configuration and server session helpers.
- `lib/schemas/`: versioned, runtime-validated content contracts shared by authoring, preview, and export.
- `lib/export/`: shared export runtime logic and learner progress interfaces.
- `lib/dashboard/`: validated folder/course operations, ownership-scoped queries, and dashboard request helpers.
- `lib/<domain>/services/`: server-side operations grouped by the dashboard, editor, and media page/API areas that use them.
- `export/`: standalone static export entry point and build configuration. It must not import Next.js server code, MongoDB, Auth.js, or private storage credentials.
- `models/`: Mongoose models; lessons and assets are independent documents rather than a giant course document.
- `tests/`: Vitest unit, component, and transactional integration tests.
- `e2e/`: Playwright tests against an isolated production build of this application.
- `scripts/testing/`: disposable replica-set lifecycle, synthetic fixtures, and production application verification; never uses the application's database configuration.

The standalone export runtime is bundled separately by Vite as a build tool inside this repository. Its build output consists only of static HTML, CSS, and JavaScript. The authenticated HTML publishing route embeds that bundle, the validated course snapshot, and owner-scoped course media in one downloadable HTML file. The SCORM 1.2 publishing route packages the same compiled export runtime with a validated snapshot, owner-scoped media, the root-level `imsmanifest.xml`, and the referenced schema files. SCORM 2004 uses the same runtime and packaged media with its own manifest and `API_1484_11` adapter. The PDF handout route validates the same course snapshot, includes owner-scoped PNG and JPEG images, and renders lesson and activity text with bundled Latin and Khmer fonts. Quiz handouts show prompts and choices without answer keys or feedback. The browser-only export saves resume and completion state through either LMS API when available; without an LMS it falls back to browser storage.

The browser-only learner view lives in `app/courses/[courseId]/preview/course-preview.tsx` and is shared by the authenticated preview route and the standalone Vite entry point. App-only navigation and publishing actions are supplied by the preview route wrapper, so the static export does not depend on Next.js APIs. The SCORM adapter lives in `export/src/scorm-runtime.ts` and depends only on browser APIs and the shared learner progress contract. Quiz best scores and passed-quiz IDs are saved with resume state; the adapter reports raw scores as attempts are graded and reports assessment success with course completion. Both outputs use `app/globals.css` for matching layout, typography, and animations.

Video/audio blocks with `allowSkipping: false` verify continuous browser `played` ranges from the beginning before awarding their existing watched/listened completion ID at the natural end. Seeking forward returns to the furthest continuously played position; rewinding, pausing and replaying covered content remain available. Standard, presentation and cropped players share the browser-only guard in `lib/export/media-playback.ts`, including static HTML/SCORM. Presentation loops wait until initial completion so the first natural end can award progress. Presentation menu circles start at zero for slides with required activities. Native media contributes ten duration-based checkpoints (10% through 90%, then 100% at playback completion under the configured skipping policy), combined equally with other required action IDs and required Continue actions. Merely viewing the slide, first accordion section or first process step earns no activity credit. Process navigation acknowledges the displayed step on leaving it. Pausing, buffering, skipping and repeated coverage earn no duplicate credit. Completion indicators live only in the preview menu; media players retain their existing native controls. Standard lessons include the same 10% video/audio checkpoints in their activity credit, keeping the existing equal reading/activity weights and completed-lesson course calculation. For example, a fully read lesson with one required recording is 75% complete after 50% verified playback and reaches 100% only after playback finishes. Slides without required activities retain their existing reading behavior. Completion IDs and navigation gates stay binary. In both Standard and Presentation modes, source-bound, duration-validated partial checkpoints resume through browser storage and compact SCORM suspend data; embedded HTML registers stable asset IDs for newly created blob URLs. Replacing an asset discards its incompatible playback credit. SCORM drops partial checkpoints first when its suspend-data budget is exhausted, preserving existing completion/gate state. Completed IDs retain unrestricted review across resume. Optional blocks remain nonblocking. Authoring players, external video links and separate audio-instruction narration retain their existing behavior. Existing required-activity and navigation gates consume the same completion IDs without schema or server changes.

Presentation video Playback settings add an optional validated `slidePlayback.revisitBehavior` of `restart` or `continue`; missing settings resolve to Restart. Leaving a slide pauses its video. Returning resets the playhead to zero or retains its exact last position, always paused. Presentation video components keep their native elements and verified played ranges across visits; rewinding does not erase checkpoints or completed activity IDs. First-visit autoplay waits for browser/LMS progress restoration and skips completed videos; native autoplay cannot independently replay a revisit. Explicit Play and Restart slide remain available. A revisit before metadata loads still applies its rewind after progress restoration. Initial browser/LMS partial-checkpoint resume remains available. This setting follows normal block validation, saving, undo and export serialization. Preview and static HTML/SCORM share the same browser-only lifecycle; audio, narration, standard courses and external-video links keep their existing playback behavior.

Resume selection accepts only lesson IDs still present in the current course. A removed or stale saved slide falls back to the first available slide, preventing a presentation with navigation but no visible content after re-exporting an edited course. Valid explicit lesson requests retain priority over valid browser/LMS resume. `scripts/testing/html-export-browser.mjs` verifies the compiled runtime embedded in a single-file HTML document opened through `file://`, including fresh launch, deleted-slide recovery, valid resume, visible canvas geometry, and fully inlined fonts without network requests.

Presentation slides share `lib/editor/slide-design.ts` contracts across editor, learner preview, and static export. A lesson's optional `slideCover` selects the image cover surface; the editor inserts a separate first lesson when existing content would otherwise be hidden. Cover image and instruction audio saves verify ready ownership in the current course, and existing recursive media packaging remaps their URLs for standalone output. The Start button uses the same lesson navigation lock as ordinary slide controls. Slide objects save percentage geometry on pointer release; selecting a layer raises it only in the editor view, preserving stored position and layer order. Heading, rich-text, and statement objects reuse the existing TipTap editors directly on the canvas. The inspector's formatting toolbar targets the focused canvas editor, keeping controls outside the scaled and clipped slide. Text selection does not start object dragging; a separate move handle preserves positioning. Inline edits use the existing block HTML contracts and revision-checked autosave, so preview and static export retain their formatting.

Presentation object frames use the full slide canvas, including header and footer space. The slide master's `objectLayout: "canvas"` marker distinguishes these coordinates from earlier content-region frames. Older slides are converted to visually equivalent full-canvas positions in the editor draft and at learner/thumbnail render time; the marker is saved with normal course edits. Footer navigation stays interactive above overlapping objects, while objects can cover decorative header and footer content. Quiz slides retain their own scrollable content region.

Every selected presentation block has a move handle, eight edge/corner resize points, and a circular rotation handle, shared with popup mini slides. Pointer deltas use logical canvas pixels at any editor zoom; resizing follows the object's rotated axes and fixes the opposite edge or corner while respecting frame limits. Image/video resizing preserves proportions. Optional `slideFrame.rotation` stores validated degrees from 0 to 360; older frames remain unrotated. Shift snaps pointer rotation to 15 degrees, and the inspector offers numeric rotation. Focused handles support arrow keys, with Shift increasing movement or rotation steps. Each completed gesture commits once through normal undo/redo and revision-checked autosave; Escape, pointer cancellation and lost capture discard drafts. Text keeps inline editing, and manual resizing turns off content fitting. Manual audio height changes set `slidePlayback.fitHeight: false`; selecting an audio size preset restores automatic player fitting. Editor, thumbnails, learner preview and static HTML/SCORM use the shared frame style's individual CSS rotation, composing with entrance animations without changing saved geometry.

Presentation slide titles may be empty to leave the visible header blank. Standard lesson titles remain required by the editor snapshot schema, and blank slides use a numbered fallback in thumbnail, navigation, and accessibility labels.

Presentation object copying uses native `copy` and `paste` events for Ctrl+C/Ctrl+V and macOS Command+C/Command+V. The selected object is captured in a versioned, Zod-validated clipboard payload with its resolved frame and source course ID, using a custom MIME type plus a plain-text fallback. Pasting within the same course preserves exact coordinates, dimensions, rotation, styling, animation and media references; fresh object/nested IDs and a front layer make each copy independent. Existing target links are kept only when their target exists on the destination slide, while nested popup links are remapped. A paste is one normal undoable autosave edit and selects the new object; copying does not edit the course. Editable fields, inline text and browser text selections keep native clipboard behavior. Only the topmost editor handles clipboard events, so popup editors cannot also paste into their parent. Existing 500-object slide, 20-object popup, nesting and cover audio-instruction restrictions apply. Server ownership checks remain on the existing save path.

Presentation audio objects hide the file name by default and render the native audio bar without lesson padding. Position & size offers Small, Medium, and Large presets with 24%, 32%, and 48% canvas widths and 32, 54, and 68 pixel player heights. The validated optional `slidePlayback.audioSize` stores the chosen player density; new blocks and unconfigured players default to Small, while explicitly selected Medium/Large sizes and custom numeric widths remain available. Small also reduces title spacing, icon size and the play button when player controls are hidden. Selecting a larger preset near the right edge moves the object inside the canvas. The editor fits the object's height to its player and optional title while preserving its authored width; title wrapping and player control changes trigger another measurement in logical canvas pixels, independent of editor zoom. Audio alone allows frames down to 0.5% height so tall custom canvases retain the compact bar. Derived fitting stays with the author's edit for undo/redo. The saved frame and shared player render in mini slides, thumbnails, preview, and static exports. Authors can enable the title through Playback settings; the original file name remains the player's accessible label.

The presentation preview menu reports a slide's summed audio/video duration after browser metadata is available and shows the sum for slides whose playable media durations are known. Players report cached metadata on mount and slide activation as well as native metadata/duration events, so paused, unvisited and retained video players do not depend on playback or a repeated metadata event to populate the menu. Duration events read their current media target directly. External video pages and audio-instruction narration are excluded; a slide with incomplete media metadata omits its duration until all playable audio/video blocks report a duration.

Each presentation block has an optional validated `slideBackground` with a solid hex color or a two-stop linear gradient and background opacity from 0 to 100. Blocks default to transparent in presentation layouts; their standard lesson background settings stay separate. The editor, preview, and static learner paint the fill once on the object frame, leaving nested content surfaces transparent and text/media at full opacity. The shared surface helper uses master text colors for transparent blocks and computes text contrast against the fill blended with the slide background for colored blocks.

Presentation color controls share the configured UI primitives through `ColorPicker`: 32-pixel square swatches with a 4-pixel radius, editable hex inputs, a Solid/Gradient toggle, two gradient stops, and a 0–360 degree angle. Invalid hex drafts stay local until valid and reset on blur. Color fields retain plain hex strings for solid colors and save bounded canonical two-stop `linear-gradient` strings for gradients; runtime validation rejects arbitrary CSS, URLs, and injected declarations. The shared rendering helpers paint gradient backgrounds and borders, clip gradient text, provide solid fallback colors for color-only CSS properties, and keep opacity on the fill alone. Interactive point fills, number text, radar rings, cards, dividers, process accents, lesson-map checkpoints, chart fills/strokes, and slide/header/footer colors use the same values. SVG charts and decorative backgrounds define unique gradients per instance. Inline text gradients retain their validated mark metadata through editing and reload. Preview, thumbnails, and static exports share these renderers and require no new server API.

New author-created interactive activities and media/audio instructions default to Optional in Free/Sequential navigation and Required in Restricted navigation, including nested popup slides. All new button blocks (Continue divider variants and interaction buttons) default to Required in every mode. Switching into/out of Restricted applies Required/Optional only to non-button activities and media; every button preserves its individual saved setting, including Optional and legacy omitted flags. Both navigation menus make this one undoable, autosaved edit. Same-mode reselection and Free/Sequential changes preserve individual choices. Copies and template replacements retain their settings. Generation applies insertion defaults using the current mode when saving the new lesson. Existing courses are not rewritten on read, and shared preview/static export progress honors the saved flags.

Button progress requirements are independent of course navigation mode. Continue buttons and interaction buttons keep their authored Required/Optional choice through every navigation change, including inside nested popup slides; new buttons start Required.
